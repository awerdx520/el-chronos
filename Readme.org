* 项目定位

=el-chronos= 是一个在 Emacs 内常驻运行的**低开销性能与用法观测器**：持续采集命令耗时、
函数热点、命令外阻塞与用法统计，落库到 SQLite，并据此回答"长期慢在哪、那次改动是否引入回归"。
它观测而不干预——不做自动调优，不改变 Emacs 的行为语义。

命名取意：=chronos= 是时间之神，本项目做的是"给 Emacs 记账"。

* 它回答的 6 条目标

| # | 问题 | 主要数据来源 |
|---|---|---|
| 1 | 哪些命令/操作慢，慢多久（含被 =C-g= 中断的卡顿）？ | =commands= 明细（=ok= / =aborted= / =error= 三态）+ =slow_events= |
| 2 | 慢在哪个函数、调用链是什么？ | =hourly_functions= 的 self/total + =hourly_stacks= 的 top-N 栈 |
| 3 | 归因到哪个 straight 包 / =lisp/init-*.el= 模块 / site-lisp 文件？ | =attrib= 归因（符号 → 源码文件 → 包/模块） |
| 4 | 长期趋势如何、某次改动是否引入回归？ | =hourly_*= 小时聚合 + 回归判定（近 N 天 vs 前 N 天） |
| 5 | 哪些高频用法值得优先优化？ | =hourly_usage= 的 command / mode / project 维度 |
| 6 | 怎么把它们都看见？ | 两种形态：org 报告 / 浏览器 Web dashboard |

* 安装

** 前置条件

- Emacs **29.1+**，且编译时带 SQLite 支持：=M-: (and (fboundp 'sqlite-open) (sqlite-available-p))= → =t=
- 可选：=straight.el=（用 =:local-repo= 安装时）

** straight.el（本包是独立仓库，用 =:local-repo=）

#+BEGIN_SRC elisp
(straight-use-package
 '(el-chronos :type built-in :local-repo "~/Workspace/el-chronos"))

(require 'el-chronos)
(el-chronos-mode 1)             ; 启动观测
#+END_SRC

** 手动 =load-path=

#+BEGIN_SRC elisp
(add-to-list 'load-path "~/Workspace/el-chronos")
(require 'el-chronos)
(el-chronos-mode 1)
#+END_SRC

* 使用（两种形态）

| 形态 | 启动 | 适合 |
|---|---|---|
| org 报告 | =M-x el-chronos-report=（默认近 7 天，可 =1d= / =30d=） | 归档、版本间 diff；=M-x el-chronos-weekly-report= 写周报，=M-x el-chronos-export= 导出 CSV/JSON |
| 浏览器 Web dashboard | =M-x el-chronos-web-start=（默认 =http://127.0.0.1:8787/=） | 深度分析：多图表、火焰图、搜索/排序/分页、多会话对比、CSV 导出 |

单条命令的深挖：=M-x el-chronos-profile-command= 在 1ms CPU 采样下**当场**跑一次命令并生成剖析报告
（热点 / 调用链 / 包归属 / 优化建议），不查库、不依赖历史数据。

两种形态的约束一致：

- **只读**：都只查库，不写库、不改配置、不改 Emacs 行为。
- **数据同源**：共享同一 =el-chronos-analysis= 查询层，两边数字不会对不上。
- **降级可见**：端口占用 → 明确报错，不自动换端口、不静默失败（I11）。

* 依赖

| 部分 | 依赖 | 说明 |
|---|---|---|
| 核心（入口 / 采集 / 归因 / 存储 / 分析 / 报告） | **零第三方** | 只用内置 =sqlite= / =profiler= / =cl-lib= / =subr-x= / =org= |
| Web dashboard（=el-chronos-web.el=） | **零依赖** | 内置 =make-network-process= 自写最小 HTTP server，HTML/CSS/JS 以字符串内嵌，无 CDN（I10） |

* 非目标

- **不自动调优**：不自动禁用功能、不自动改配置、不自动"修"性能问题。
- **不做云同步 / 多机汇聚**：数据只落本机，不上报云端，也不做多机聚合。
- **不做行级采样**：ELisp profiler 只记录符号栈，无源码行号；定位粒度到"函数 + 调用链"为止。
- **不记按键序列与文件内容**：默认只记命令名、耗时、mode、project basename。

* 隐私与数据保留

边界按「归因与趋势是否必需」逐项划定：

- **记录**：命令名、耗时、GC 耗时、major-mode、项目 **basename**、结果（正常/中断/报错）、
  函数符号名、函数定义源码路径（后者只为归因到包/模块，不含被操作对象信息）。
- **不记录**：被操作文件路径、buffer 内容、按键序列、命令参数、剪贴板、环境变量。

=commands.project= 存的是 **project basename**（=file-name-nondirectory= 处理后的目录名），
**不是绝对路径**；取不到时为 NULL。因此即使数据库被拷走，也拿不到「你编辑了哪些文件」。

唯一例外：用户**主动**把 =el-chronos-usage-granularity= 改为 =file= 时，=hourly_usage= 会记录
被操作文件的**绝对路径**，而该表**永久保留**（只能 =el-chronos-purge= 清）。默认 =command=，不记任何路径。

| 表 | 保留 |
|---|---|
| =commands= / =slow_events=（明细） | =el-chronos-retention-days=（默认 30 天）自动清理 |
| =hourly_functions= / =hourly_usage= / =hourly_stacks=（聚合） | **永久保留**，只由 =M-x el-chronos-purge= 手动清理 |

数据库默认落 =<user-emacs-directory>/.local/state/chronos/chronos.sqlite=
（连同 =chronos.sqlite-wal= / =-shm=），位于版本控制与备份系统通常忽略的状态目录内。

**Web 形态的边界**：Web dashboard **无鉴权**；只绑 =127.0.0.1= 只能防住 LAN 暴露，
**不构成本机访问控制**——本机 WSL2 mirrored 网络下 Windows 侧进程可直接访问该端口。
定位是「本机自用的只读视图」：默认不启动，用完即 =M-x el-chronos-web-stop=，
不要在有不可信本地进程或多用户共享的环境里长期开着。

* 卸载与数据清理

1. =(el-chronos-mode -1)= —— 清理 timer、hook（含每 buffer 的局部 hook）、profiler、未 flush 缓冲（零残留）。
2. 从配置里删掉 =(require 'el-chronos)= / straight 段并移除 =load-path=（可选：删除本地 clone）。
3. 删数据（可选）：先做完第 1 步，再删
   =<user-emacs-directory>/.local/state/chronos/chronos.sqlite=（连同 =-wal= / =-shm=）。

数据清理两条路径（不必卸载也能用）：

- **保留式清理**：=M-x el-chronos-purge= 输入日期 =YYYY-MM-DD= → 删除该日期**之前**的全部数据（含小时聚合）；
  直接回车 → 清空全部 6 张表。之后建议 =M-x el-chronos-store-vacuum= 回收文件空间。
- **直接删文件**：关闭 Emacs 后 =rm ~/.emacs.d/.local/state/chronos/chronos.sqlite*=，下次启动重建空库。

完整运维步骤（含按平台差异的排障）见 [[file:docs/operations.org][docs/operations.org]]。

* 验证与测试

全部走 =emacs -Q --batch=，不依赖运行中的 daemon，也不碰你自己的 daemon：

#+BEGIN_SRC sh
make check-parens   # L1：逐文件括号平衡
make lint           # L1 补充：字节编译告警（输出到临时目录，不污染仓库）
make test           # L2：自动发现 test/*-test.el 并跑全部 ERT（当前 109 用例）
make full-check     # check-parens + test
#+END_SRC

测试文件固定命名 =test/*-test.el=（Makefile 用 =$(wildcard test/*-test.el)= 自动发现，
新增测试无需改 Makefile）。手动 smoke：开 mode → **真实操作 1 分钟**（纯静止不产生 CPU 样本）→
=M-x el-chronos-report=；详细清单见 [[file:docs/operations.org][docs/operations.org]]「验证步骤」。
