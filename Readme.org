* 项目定位

=el-chronos= 是一个在 Emacs 内常驻运行的**低开销性能与用法观测器**：持续采集命令耗时、
函数热点、命令外阻塞与用法统计，落库到 SQLite，并据此回答"长期慢在哪、那次改动是否引入回归"。
它观测而不干预——不做自动调优，不改变 Emacs 的行为语义。

观测面已从「时间」扩展到「**时间 + 内存/GC + 启动 + 配置变更**」
（[[file:docs/adr/0004-observation-surface-expansion.md][ADR-0004]]）：除命令与采样之外，还按小时采集
GC 次数/耗时与 Emacs 堆大小、按会话分解启动阶段与包加载、并记录配置仓库的提交 sha 与配置文件指纹
（后者只取相对路径 + mtime + size，**不读文件内容**）。

命名取意：=chronos= 是时间之神，本项目做的是"给 Emacs 记账"。

启动与资源两个维度由 [[file:docs/adr/0006-resource-observation.md][ADR-0006]] 补齐：

- **启动分解**（需 =early-init= 探针）：=early-init= / =after-init= / =startup= 三锚点 + 按包累计的加载耗时，
  由独立**零依赖**探针 =el-chronos-startup-probe.el= 在 =early-init.el= 里提前上岗采集（装法见后文
  「启动探针（推荐：在 =early-init= 里加载）」）——不装探针时只有 =mode-start= 一个锚点（物理边界，TD-16）。
- **资源画像**（CPU / RSS / 负载）：Emacs 进程 CPU 毫秒、RSS（KB）、线程数、系统负载 1/5/15，
  并入既有 10 秒采样 timer（**不新增 timer**），只查自己这个 pid，不遍历系统进程、不读 buffer 内容。

* 它回答的 6 条目标

| # | 问题 | 主要数据来源 |
|---|---|---|
| 1 | 哪些命令/操作慢，慢多久（含被 =C-g= 中断的卡顿）？ | =commands= 明细（=ok= / =aborted= / =error= 三态）+ =slow_events= |
| 2 | 慢在哪个函数、调用链是什么？ | =hourly_functions= 的 self/total + =hourly_stacks= 的 top-N 栈 |
| 3 | 归因到哪个 straight 包 / =lisp/init-*.el= 模块 / site-lisp 文件？ | =attrib= 归因（符号 → 源码文件 → 包/模块） |
| 4 | 长期趋势如何、某次改动是否引入回归？ | 七张 =hourly_*= 小时聚合表（含 =hourly_resources= 的 CPU / RSS / 负载）+ 回归判定（近 N 天 vs 前 N 天） |
| 5 | 哪些高频用法值得优先优化？ | =hourly_usage= 的 command / mode / project 维度 |
| 6 | 怎么把它们都看见？ | 两种形态：org 报告（**16 节**）/ 浏览器 Web dashboard（**19 条只读 GET 路由** = 1 页 + 18 条 =/api/*=（17 JSON + 1 CSV）） |

* 安装

** 前置条件

- Emacs **29.1+**，且编译时带 SQLite 支持：=M-: (and (fboundp 'sqlite-open) (sqlite-available-p))= → =t=
- 可选：=straight.el=（用 =:local-repo= 安装时）

** straight.el（方式 A：推荐，=:local-repo= 指向开发仓）

本地开发仓与远端仓库是同一份代码：=:local-repo= 让 straight 软链本地工作树加载，
=:type= / =:host= / =:repo= / =:branch= 保留 upstream 识别（与 =seshat-reader= 同款写法）。

#+BEGIN_SRC elisp
(straight-use-package
 '(el-chronos :type git
              :host github
              :repo "awerdx520/el-chronos"
              :branch "master"
              :local-repo "/home/thomas/Workspace/el-chronos"
              :files ("el-chronos*.el" (:exclude "el-chronos-autoloads.el"))
              :build (:not compile native-compile)))

(require 'el-chronos)
(el-chronos-mode 1)             ; 启动观测
#+END_SRC

recipe 三处非默认值，各有实测理由：

- =:local-repo "/home/thomas/Workspace/el-chronos"= —— 源码经
  =<straight-base-dir>/straight/build-<ver>/el-chronos/= 下的**软链**加载，改完源仓库后
  =M-x straight-rebuild-package RET el-chronos= 即生效，无需 push / pull / 重开 Emacs。
  **注意**：straight 的 =straight-pull-package= / =straight-checkout-package= 会**直接作用在你的
  开发仓上**（它就是那个 git 仓库），工作区有未提交改动时慎跑。
- =:files ("el-chronos*.el" (:exclude "el-chronos-autoloads.el"))= —— 只取仓库根模块，并**显式排除**
  =make autoloads= 的生成物：straight 自己的 autoloads 步骤要写同名文件，若该名字被软链进 build 目录
  就会穿透写回源仓库。
- =:build (:not compile native-compile)= —— **保留** autoloads、禁用字节与 native 编译：
  包侧 =;;;###autoload= cookie 于是真正生效（16 个 interactive 命令全部免配置可 =M-x=），
  同时不产生 =.elc= / =.eln= 副本，源码改动立刻可见。
  代价：**新增或改名 interactive 命令后**要 =M-x straight-rebuild-package RET el-chronos=
  刷新 autoloads，否则新命令不在 autoload 表里。

** 手动 =load-path=（方式 B：无 straight）

#+BEGIN_SRC elisp
(add-to-list 'load-path "~/Workspace/el-chronos")
(require 'el-chronos)
(el-chronos-mode 1)
#+END_SRC

此形态没有 straight 的 autoloads 步骤，入口命令须逐条手写（库名必须等于**定义文件名**，
否则首次 =M-x= 报 =Autoloading file ... failed to define function=）：

#+BEGIN_SRC elisp
(autoload 'el-chronos-report "el-chronos-report" nil t)
(autoload 'el-chronos-weekly-report "el-chronos-report" nil t)
(autoload 'el-chronos-profile-command "el-chronos-report" nil t)
(autoload 'el-chronos-web-start "el-chronos-web" nil t)
(autoload 'el-chronos-web-stop "el-chronos-web" nil t)
#+END_SRC

入口 =load-path= 只写**字符串字面量**：绝对路径最稳、=~= 前缀亦可（依赖 HOME 展开）。
禁止相对路径与 =(expand-file-name ...)= / 变量形态——在 =use-package= 的 =:load-path= 里后者会让
整个 form 展开为 =nil=（静默失效），手写 =add-to-list= 时则会把当时 =default-directory= 固化进去。

** 方式 C：use-package（已有配置框架的用户）

=use-package= 只是组织形态，安装仍是方式 A 那条 =:straight= recipe —— 包侧 15 条
=;;;###autoload= cookie 由 straight 的 autoloads 步骤生成，因此**不必**逐条手写
=(autoload SYM "FILE")=，也**不要**退回 =:straight nil= + =:load-path= 的手动形态
（那是「方式 B」的自动化版本，实测踩过四个静默陷阱）。

#+BEGIN_SRC elisp
;; 注意：降级判据必须用 if 包住整个 use-package —— use-package 的 :if 包不住 :straight
;; （实测展开仍含 straight-use-package，目录缺失时会去远端 clone），详见下面「陷阱」节
(if (file-exists-p "/home/thomas/Workspace/el-chronos/el-chronos.el")
    (use-package el-chronos
      :straight (el-chronos
                 :type git
                 :host github
                 :repo "awerdx520/el-chronos"
                 :branch "master"
                 :local-repo "/home/thomas/Workspace/el-chronos"
                 :files ("el-chronos*.el" (:exclude "el-chronos-autoloads.el"))
                 :build (:not compile native-compile))
      :demand t                    ; 模式必须尽早启用（理由见下「为什么不建议 :defer t」）
      :config
      ;; 实例守卫（可选示例）：本机 thomas-emacs 用它避免在隔离实例里启用观测
      (unless (member (getenv "THOMAS_EMACS_INSTANCE") '("isolated" "pure"))
        ;; 必须 lambda 形态：#'el-chronos-mode 交给 add-hook 会被无参调用 = toggle 模式
        (add-hook 'emacs-startup-hook (lambda () (el-chronos-mode 1)))))
  ;; 仓库缺失：只告警、不阻断启动
  (display-warning 'chronos "未找到 el-chronos，性能与用法观测不可用" :warning))
#+END_SRC

四个关键字逐条说明（=:straight= 的 recipe 内部各项与实测理由见方式 A）：

- =if (file-exists-p ...) ...= —— 观测器是可选组件：仓库不存在时整个 =use-package= form 不求值
  （不 clone、不 require），启动照常完成，=display-warning= 分支给出「性能与用法观测不可用」提示、不静默。
  **不要**改成 =use-package= 的 =:if=：=:if= 只包住 =require=，包不住 =:straight= 生成的安装调用
  （实测见下面「陷阱」节第一条）。
- =:straight (el-chronos ...)= —— **不要**写 =:straight nil=：本机
  =straight-use-package-by-default= 为 =t=，缺了 =:straight= 会展开成
  =(straight-use-package 'el-chronos)= 去解析 recipe / 尝试远端安装；写成完整 recipe 才是
  「本地开发仓源码 + upstream 识别」的形态。
- =:demand t= —— 立即 =require=，模式才能尽早启用（理由见下「为什么不建议 =:defer t」）。
- =:config= 内 =add-hook 'emacs-startup-hook (lambda () (el-chronos-mode 1))= —— 不要写成
  =#'el-chronos-mode=：=add-hook= 投递符号后是**无参调用**，而 =el-chronos-mode= 的无参形态是
  **toggle**，重复求值会把观测关掉。实例守卫那段是可选项示例（本机 thomas-emacs 用
  =THOMAS_EMACS_INSTANCE= 跳过隔离实例），照抄时按自己的环境改。

** 方式 C 的三个新增陷阱（实测 Emacs 31.1 / straight 当前版本）

- **=:if= / =:when= 包不住 straight 安装** —— 需要「仓库缺失就降级」时必须用 =if= 包住**整个**
  =use-package=，写成 =:if (file-exists-p ...)= 无效。实测
  =(macroexpand-1 '(use-package el-chronos :if nil :straight (el-chronos ...)))= 展开为
  =(progn (straight-use-package '(el-chronos ...)) (when nil (require 'el-chronos nil nil)))= ——
  安装调用在顶层、=:if= 之外；=:if= 为假时照样执行，本机表现为目录缺失也会去远端 clone 本仓。
  正确形态 =if (file-exists-p ...) (use-package ...) (display-warning ...)= 展开为
  =(if COND (progn (straight-use-package '...) ...) ...)=，条件为假时整段不求值。
- **=straight-pull-package= / =straight-checkout-package= 直接作用在开发仓上** —— =:local-repo=
  指向的就是你的 git 工作树（straight 不复刻一份副本），这两条命令会改它。开发时勿让工作区处于
  未提交状态再跑。
- **新增 / 改名 interactive 命令后要 rebuild 才有 autoload** —— =:build (:not compile
  native-compile)= 保留 autoloads 生成，但生成只发生在 build 时；命令清单变了而没 rebuild 时，
  新命令不在 autoload 表里（=M-x= 找不到）。修法：=M-x straight-rebuild-package RET el-chronos=。

> 若你选择 =:load-path= 而不是 =:local-repo=（不推荐）：它只能写**字符串字面量**——绝对路径最稳、
> =~= 前缀亦可；禁止相对路径（宏展开期按当时 =user-emacs-directory= 固化成绝对路径，隔离实例里
> 等于静默指向错误目录），也禁止 =(expand-file-name ...)= 或变量形态（整个 form 展开为 =nil=，
> 静默失效）。此时 autoload 须逐条手写（库名 = 定义文件名；=:autoload= / =:commands= 做不到跨文件），
> 明细见 [[file:docs/operations.org][docs/operations.org]]「autoload 契约」与「四个静默陷阱」。

** 为什么不建议 =:defer t=

延迟加载对本包是**净损失**，不是优化：

- =startup_phases= 的**包加载明细**只在 =el-chronos-mode= 早于 =after-init-hook= 启用时才存在。
  模式晚启用（=:defer t=，或挂在 =emacs-startup-hook= 上）时，启动分解只剩 =mode-start= 一个锚点、
  没有任何包加载明细——观测器无法观测自己被加载之前发生的事，这是物理边界不是 bug
  （见 [[file:docs/operations.org][docs/operations.org]]「启动分解的物理边界」）。
- 延迟也省不到什么：=el-chronos.el= 本身很薄，真正的重活（=sqlite= / =org=）本来就在 mode 启动
  之后的首次需要时才加载。
- 需要「只在看报告时才加载」的延迟形态不在设计目标内：代价就是拿不到启动分解。

** 启动探针（推荐：在 =early-init.el= 里加载）

观察器本体挂在 =emacs-startup-hook= 上启用，那时 init 文件已全部加载完，采集侧按既定设计
**不再挂**包加载钩子（否则启动后的交互式 =load= 会被记成「启动耗时」）——于是 =startup_phases=
只剩 =mode-start= 一行、=load:*= 明细 **0 条**（实测 20/20 会话）。要测到 init 主体，须让**独立探针**
在 =early-init.el= 里先上岗。探针零依赖、只写内存：不开 SQLite、不写文件、所有入口 =condition-case= 包裹，
数据等 =(el-chronos-mode 1)= 之后由采集侧取走写库。

#+BEGIN_SRC elisp
;; early-init.el（必须在 init 主体之前求值）
;; 三重防护，缺一不可（这段跑在启动主路径上，出错即起不来）：
;;   1. 实例守卫——隔离实例 / 纯实例不装探针（与 init-chronos.el 同一判据）
;;   2. file-exists-p——仓库搬迁 / 改名时静默跳过
;;   3. load 的 NOERROR——探针缺失或损坏时绝不打断启动
(unless (member (getenv "THOMAS_EMACS_INSTANCE") '("isolated" "pure"))
  (let ((chronos-probe "/home/thomas/Workspace/el-chronos/el-chronos-startup-probe.el"))
    (when (file-exists-p chronos-probe)
      (ignore-errors (load chronos-probe t t t)))))
#+END_SRC

三点必须照做：

1. **用绝对路径 =load=，不要 =require=，也不要为此 =add-to-list 'load-path=**——探针不在 =load-path=
   上（也不该在：early-init 期 =straight/build-*= 还没建立），=require= 必然失败，而把仓库根塞进全局
   =load-path= 会污染所有后续加载。仓库改名 / 搬迁后 =(load ... t)= 按 NOERROR 语义**静默失败**，
   表现就是 =load:*= 明细又变回 0 条——**排障口诀：=load:*= 为 0 先确认这个路径存在**。
2. **三个 =t=** 是 NOERROR / NOMESSAGE / NOSUFFIX，缺了任何一个都可能让探针缺失变成启动错误。
3. **多实例环境要加实例守卫**（示例里的 =THOMAS_EMACS_INSTANCE=）：隔离实例（=elisp-test=）与纯实例
   （=elisp-pure=）是一次性验证环境，不需要启动分解数据，装了只会让验证结果里混进无关行。

不装探针的降级行为：启动分解仍只有 =mode-start= 一个锚点，报告与 Web 的标题都标注覆盖范围
（「自 mode 启动起 X ms / 总 Y ms」），**不会**把近似数据冒充全程；其余观测（命令、采样、GC、资源、用法）
完全不受影响。装了探针的残留边界：load 明细覆盖到「最后一次取走（take）时刻」，=startup= 锚点之后到
事件循环之间的少量加载可能缺失。

探针的收尾有三条自证路径（正常 =emacs-startup-hook= 回调 / 加载数达 800 兜底 / =after-init= 后 30 秒
兜底 timer），全部汇到 =--finish= 自摘钩子并取消 timer，不会在启动后继续挂着。注意它**不在**
=el-chronos-mode= 的生命周期内：=M-x el-chronos-mode= 关掉观测**不会**摘它（I5 的零残留不覆盖它，
见 ADR-0006 D1）。

* 使用（两种形态）

| 形态 | 启动 | 适合 |
|---|---|---|
| org 报告 | =M-x el-chronos-report=（**16 节**，默认近 7 天，可 =1d= / =30d=） | 归档、版本间 diff；=M-x el-chronos-weekly-report= 写周报，=M-x el-chronos-export= 导出 CSV/JSON |
| 浏览器 Web dashboard | =M-x el-chronos-web-start=（默认 =http://127.0.0.1:8787/=，**19 条只读 GET 路由** = 1 页 + 18 条 =/api/*=） | 深度分析：多图表、火焰图、搜索/排序/分页、多会话对比、CSV 导出 |

单条命令的深挖：=M-x el-chronos-profile-command= 在 1ms CPU 采样下**当场**跑一次命令并生成剖析报告
（热点 / 调用链 / 包归属 / 优化建议），不查库、不依赖历史数据；结果默认只出报告、不落库
（=el-chronos-profile-save= 为 =t= 时才写 =slow_events=，避免与常规采集的窗口口径混在一起）。

两种形态的约束一致：

- **只读**：都只查库，不写库、不改配置、不改 Emacs 行为。
- **数据同源**：共享同一 =el-chronos-analysis= 查询层，两边数字不会对不上。
- **降级可见**：端口占用 → 明确报错，不自动换端口、不静默失败（I11）。

**浏览器自动打开（Web dashboard）**：交互式 =M-x el-chronos-web-start= 在启动后默认用 =browse-url=
打开页面，开关是 =el-chronos-web-open-browser=（默认 =t=）；设为 =nil= 时只在 echo area 显示 URL。
两个必知边界：

- **程序化启动绝不弹浏览器**（=el-chronos-web-auto-start= 在启用观测时顺带起 server 的那条路径），
  否则每次启动 Emacs 都会弹一个窗口。
- =M-x el-chronos-web-browse= 是「现在就打开看」的命令：**不看**这个开关，每次调用都打开当前页，
  server 未运行时先启动再打开（先启动那次是非交互调用、天然不弹，因此不会双弹）。打开失败只
  =message= 提示并给出 URL，不影响 server 运行（I11：可见降级、不中断）。

**启动分解的物理边界**：=startup_phases= 的包加载明细只能覆盖采集起步**之后**发生的 =load=
（观测器无法观测自己被加载之前的事，这是物理边界不是 bug）。若 mode 在启动结束之后才启用
（例如挂在 =emacs-startup-hook=），就只有 =mode-start= 一个锚点、没有包加载明细；要完整剖析请装
**启动探针**（见上文「启动探针（推荐：在 =early-init.el= 里加载）」），另一条路是把
=(el-chronos-mode 1)= 提前到 =early-init.el=（含副作用说明，见
[[file:docs/operations.org][docs/operations.org]]「启动分解的物理边界」）。

**堆大小采集的版本门槛**：=hourly_gc.heap_bytes= 取自 =(garbage-collect-heapsize)=，该函数 **Emacs 31.1+**
才有；更低版本这一列恒为 NULL，其余观测不受影响（最低版本要求仍是 29.1）。跨版本共用同一份库时曲线会
出现整段空洞，读趋势请按 =sessions.emacs_version= 分组（TD-15）。

* 依赖

| 部分 | 依赖 | 说明 |
|---|---|---|
| 核心（入口 / 采集 / 归因 / 存储 / 分析 / 报告） | **零第三方** | 只用内置 =sqlite= / =profiler= / =cl-lib= / =subr-x= / =org= |
| 启动探针（=el-chronos-startup-probe.el=） | **零依赖（更严格）** | 不 require 任何 el-chronos 模块，也**不** require =cl-lib= / =subr-x=，只用内置 subr；不开库、不写库（early-init 期 =straight/build-*= 尚未建立，任何 require 都可能失败） |
| Web dashboard（=el-chronos-web.el=） | **零依赖** | 内置 =make-network-process= 自写最小 HTTP server，HTML/CSS/JS 以字符串内嵌，无 CDN（I10） |

* 非目标

- **不自动调优**：不自动禁用功能、不自动改配置、不自动"修"性能问题。
- **不做云同步 / 多机汇聚**：数据只落本机，不上报云端，也不做多机聚合。
- **不做行级采样**：ELisp profiler 只记录符号栈，无源码行号；定位粒度到"函数 + 调用链"为止。
- **不记按键序列与文件内容**：默认只记命令名、耗时、mode、project basename。

* 隐私与数据保留

边界按「归因与趋势是否必需」逐项划定：

- **记录**：命令名、耗时、GC 耗时、major-mode、项目 **basename**、结果（正常/中断/报错）、
  函数符号名、函数定义源码路径（后者只为归因到包/模块，不含被操作对象信息）、
  会话级 =git-head= 与 =config-sig= —— 前者是配置仓库的**当前提交 sha**（只读 =.git/HEAD= 与
  =refs/packed-refs=，**不起 git 子进程**），后者是 =el-chronos-config-watch-globs= 命中文件的
  **相对路径 + mtime + size** 取 sha1（**不读文件内容**）；两者都取不到就**不写行**；
  会话级 =host=（=sessions.host=，=system-name= 的主机名）—— 用于区分多机数据，
  **不含**用户名与网络地址。
- **不记录**：被操作文件路径、buffer 内容、按键序列、命令参数、剪贴板、环境变量、配置文件内容。

=commands.project= 存的是 **project basename**（=file-name-nondirectory= 处理后的目录名），
**不是绝对路径**；取不到时为 NULL。因此即使数据库被拷走，也拿不到「你编辑了哪些文件」。

唯一例外：用户**主动**把 =el-chronos-usage-granularity= 改为 =file= 时，=hourly_usage= 会记录
被操作文件的**绝对路径**，而该表**永久保留**（只能 =el-chronos-purge= 清）。默认 =command=，不记任何路径。

| 表 | 保留 |
|---|---|
| =commands= / =slow_events=（明细） | =el-chronos-retention-days=（默认 30 天）自动清理 |
| 七张 =hourly_*= 聚合表（=hourly_functions= / =hourly_usage= / =hourly_stacks= / =hourly_gc= / =hourly_health= / =hourly_drift= / =hourly_resources=） | **永久保留**，只由 =M-x el-chronos-purge= 手动清理 |
| =startup_phases= / =session_meta=（会话级） | 随 =sessions= 行一起保留（=startup_phases= 每会话 ≤ =el-chronos-startup-top-n= 条加载明细 + 3 个阶段锚点，默认 ≤ 53 行，是增长最快的一张），同样只由 =M-x el-chronos-purge= 清理 |

两套清理粒度不同：七张 =hourly_*= 按**小时列**删，=startup_phases= / =session_meta= 无时间列、
只能按 =session_id= 的 =started_at= **整会话**删——跨表对账（「某会话的 GC 与启动」）时可能对不齐
（TD-17）。

=hourly_resources= 记的是**进程 / 系统级数值**——Emacs 进程 CPU 毫秒、RSS（KB）、线程数、系统负载
1/5/15——**不含任何用户内容**：只查 =(emacs-pid)= 自己的 =process-attributes=，不遍历系统进程、不读
命令行、不读 buffer。

数据库默认落 =<user-emacs-directory>/.local/state/chronos/chronos.sqlite=
（连同 =chronos.sqlite-wal= / =-shm=），位于版本控制与备份系统通常忽略的状态目录内。

**Web 形态的边界**：Web dashboard **无鉴权**；只绑 =127.0.0.1= 只能防住 LAN 暴露，
**不构成本机访问控制**——本机 WSL2 mirrored 网络下 Windows 侧进程可直接访问该端口。
定位是「本机自用的只读视图」：默认不启动，用完即 =M-x el-chronos-web-stop=，
不要在有不可信本地进程或多用户共享的环境里长期开着。

* 卸载与数据清理

1. =(el-chronos-mode -1)= —— 清理 timer、hook（含每 buffer 的局部 hook）、profiler、未 flush 缓冲（零残留）。
2. 从配置里删掉 straight recipe（=:local-repo= 软链随后消失）或 =(require 'el-chronos)= 与
   =load-path= 条目（可选：删除本地 clone）。
3. 删数据（可选）：先做完第 1 步，再删
   =<user-emacs-directory>/.local/state/chronos/chronos.sqlite=（连同 =-wal= / =-shm=）。

数据清理两条路径（不必卸载也能用）：

- **保留式清理**：=M-x el-chronos-purge= 输入日期 =YYYY-MM-DD= → 删除该日期**之前**的全部数据（含七张 =hourly_*= 与两张会话级表）；
  直接回车 → 清空全部 12 张表。之后建议 =M-x el-chronos-store-vacuum= 回收文件空间。
- **直接删文件**：关闭 Emacs 后 =rm ~/.emacs.d/.local/state/chronos/chronos.sqlite*=，下次启动重建空库。

完整运维步骤（含按平台差异的排障）见 [[file:docs/operations.org][docs/operations.org]]。

* 验证与测试

全部走 =emacs -Q --batch=，不依赖运行中的 daemon，也不碰你自己的 daemon：

#+BEGIN_SRC sh
make check-parens   # L1：逐文件括号平衡
make lint           # L1 补充：字节编译告警（输出到临时目录，不污染仓库）
make test           # L2：自动发现 test/*-test.el 并跑全部 ERT（当前 336 用例，0 skipped）
make autoloads      # 按需生成 el-chronos-autoloads.el（生成物不入库、不进 L1/L2）
make full-check     # check-parens + test
#+END_SRC

=make autoloads= 生成 =el-chronos-autoloads.el=——**16 个 interactive 命令**的 autoload 声明
（每个都指向自己的定义文件，如 =(autoload 'el-chronos-report "el-chronos-report" ...)=）。
**生成物不入库**（=.gitignore= 已忽略，改了源码按需重建即可，入库必然与源码漂移），
**也不进 L1/L2**（=EL_FILES= 的 =find= 显式排除该文件，否则生成后括号检查与字节编译的检查范围
会随生成物变化）。Emacs 29+ 用 =loaddefs-generate=，更早版本回退 =make-directory-autoloads=。

测试文件固定命名 =test/*-test.el=（Makefile 用 =$(wildcard test/*-test.el)= 自动发现，
新增测试无需改 Makefile）。336 用例分布：=collect= 87 / =store= 81 / =analysis= 57 / =report= 39 /
=attrib= 28 / =web= 25 / =startup-probe= 16 / =autoload= 3。手动 smoke：开 mode → **真实操作 1 分钟**
（纯静止不产生 CPU 样本）→ =M-x el-chronos-report=；详细清单见 [[file:docs/operations.org][docs/operations.org]]「验证步骤」。
