* 安装

** 前置条件

| 项 | 要求 | 检查方式 |
|---|---|---|
| Emacs | 29.1+（需要内置 =sqlite=） | =M-: (and (fboundp 'sqlite-open) (sqlite-available-p))= → =t= |
| SQLite | 编译期带 SQLite 支持 | =(featurep 'sqlite)= → =t= |
| straight.el | 可选（用 =:local-repo= 安装时需要） | =(featurep 'straight)= |

** 方式 A：straight.el（=:local-repo=，本包为独立仓库）

本包是独立仓库（不与 thomas-emacs 同仓），开发仓与远端是同一份代码：=:local-repo= 让 straight
软链本地工作树、=:type= / =:host= / =:repo= / =:branch= 保留 upstream 识别（与 =seshat-reader=
同款写法）。远端：=git@github.com:awerdx520/el-chronos.git=，分支 =master=。

#+BEGIN_SRC elisp
(straight-use-package
 '(el-chronos :type git
              :host github
              :repo "awerdx520/el-chronos"
              :branch "master"
              :local-repo "/home/thomas/Workspace/el-chronos"
              :files ("el-chronos*.el" (:exclude "el-chronos-autoloads.el"))
              :build (:not compile native-compile)))

(require 'el-chronos)
(el-chronos-mode 1)
#+END_SRC

三处非默认值，各有实测理由：

| recipe 项 | 作用与理由 |
|---|---|
| =:local-repo= | 源码经 =<straight-base-dir>/straight/build-<ver>/el-chronos/= 下的**软链**加载；改完源仓库后 =M-x straight-rebuild-package RET el-chronos= 即生效，无需 push / pull / 重开 Emacs |
| =:files ("el-chronos*.el" (:exclude "el-chronos-autoloads.el"))= | 只取仓库根模块，并**显式排除** =make autoloads= 的生成物：straight 的 autoloads 步骤要写同名文件，若该名字被软链进 build 目录就会穿透写回源仓库（实测：排除后 build 目录里是独立真实文件，源仓库 sha256 不变） |
| =:build (:not compile native-compile)= | **保留** autoloads、禁用字节与 native 编译：包侧 16 条 =;;;###autoload= cookie 因此真正生效（命令免配置可 =M-x=），且不产生 =.elc= / =.eln= 副本，源码改动立刻可见。代价：新增 / 改名 interactive 命令后须 rebuild 才有新 autoload |

> =straight-pull-package= / =straight-checkout-package= 会**直接改你的开发仓**（=:local-repo= 就是
> 那个 git 工作树，straight 不复刻副本）。工作区有未提交改动时慎跑。

** 方式 B：手动 =load-path=（无 straight）

#+BEGIN_SRC elisp
(add-to-list 'load-path "~/Workspace/el-chronos")
(require 'el-chronos)
(el-chronos-mode 1)
#+END_SRC

** 方式 C：use-package（已有配置框架的用户）

=use-package= 只是组织形态，安装仍是方式 A 那条 =:straight= recipe。包侧提供标准
=;;;###autoload= 契约（**16 个 interactive 命令**全部带 cookie），straight 的 autoloads 步骤会
依据 cookie 生成 autoload 声明，**不必**再逐条手写 =(autoload SYM "FILE")=。
下面整段可复制，只需把两处 =/home/thomas/Workspace/el-chronos= 换成你自己的 clone 路径、
实例守卫那行按自己的环境删改。实测环境：Emacs **31.1** / use-package **2.4.5**（Emacs 自带）。

#+BEGIN_SRC elisp
;; 降级判据必须用 if 包住整个 use-package：use-package 的 :if 包不住 :straight（见陷阱 ④）
(if (file-exists-p "/home/thomas/Workspace/el-chronos/el-chronos.el")
    (use-package el-chronos
      ;; ① 完整 recipe：本地开发仓 + upstream 识别（与方式 A 同款）
      :straight (el-chronos
                 :type git
                 :host github
                 :repo "awerdx520/el-chronos"
                 :branch "master"
                 :local-repo "/home/thomas/Workspace/el-chronos"
                 :files ("el-chronos*.el" (:exclude "el-chronos-autoloads.el"))
                 :build (:not compile native-compile))
      :demand t                                    ; ② 尽早启用（不要 :defer t）
      :config
      ;; ③ 实例守卫（可选）+ 必须 lambda 形态的 hook
      (unless (member (getenv "THOMAS_EMACS_INSTANCE") '("isolated" "pure"))
        (add-hook 'emacs-startup-hook (lambda () (el-chronos-mode 1)))))
  ;; 仓库缺失：可见性靠这条告警，不阻断启动
  (display-warning 'chronos "未找到 el-chronos，性能与用法观测不可用" :warning))
#+END_SRC

| 关键字 | 为什么必须是这个形态（实测） |
|---|---|
| =if (file-exists-p ...) ...= | 观测器是可选组件：仓库不存在时整段 =use-package= 不求值（不 clone、不 require），启动照常完成；=display-warning= 分支给出「性能与用法观测不可用」，不静默。**不要**换成 =use-package= 的 =:if=——它只包住 =require=，包不住 =:straight= 的安装调用（陷阱 ④） |
| =:straight (el-chronos ...)= | **不要**写 =:straight nil=：本机 =straight-use-package-by-default= 为 =t=，缺了 =:straight= 会展开成 =(straight-use-package 'el-chronos)= 去解析 recipe / 尝试远端安装；写成完整 recipe 才是「本地开发仓源码 + upstream 识别」的形态。recipe 内部三项（=:local-repo= / =:files= / =:build=）的理由见方式 A 的表格 |
| =:demand t= | 立即 =require=，让 mode 尽早启用。延迟加载会让启动分解退化为单锚点（见「启动分解的物理边界」节），对本包是净损失。另：=:demand t= 生成的 require 是 =(require 'el-chronos nil nil)=（=noerror= 为 nil），加载失败会直接抛错、不静默 |
| =:config=（实例守卫 + lambda） | =add-hook= 投递符号后是**无参调用**，而 =el-chronos-mode= 无参形态是 **toggle** → 必须 =(lambda () (el-chronos-mode 1))=。守卫段只是本机 thomas-emacs 的示例（它在隔离实例里跳过观测），照抄请按自己的环境改或删掉 |

> **旧形态（=:straight nil= + =:load-path=）已不推荐**：它依赖逐条手写 autoload 才让跨文件命令可用，
> 且 =:load-path= 有若干静默陷阱（见「静默陷阱」①）。若仍要用，注意 =:load-path= 只能写
> **字符串字面量**（绝对路径最稳、=~= 前缀亦可），且入口命令必须逐条 =(autoload SYM "定义文件名" nil t)=。

** 启动探针的安装（推荐，v4）

=startup_phases= 的包加载明细只在「启动尚未结束时模式已启用」才会产生。**本机实测（2026-10-26）**：
=startup_phases= 里 20 个会话全部只有 =mode-start= 一个锚点、=load:*= **0 条** —— 即不装探针时
启动分解在本机**完全不可用**（不是数据少，是一条都没有）。原因是 mode 由
=(add-hook 'emacs-startup-hook #'el-chronos-mode)= 启动，那一刻 =after-init-time= 已非 nil。

**推荐做法**：在 =early-init.el= 里加载**启动探针**（零依赖侧文件，`el-chronos-startup-probe.el`）。
最小形态两行：

#+BEGIN_SRC elisp
;; ~/.emacs.d/early-init.el（越靠前越好：探针越早上岗，覆盖的加载越多）
(when (file-exists-p "/home/thomas/Workspace/el-chronos/el-chronos-startup-probe.el")
  (load "/home/thomas/Workspace/el-chronos/el-chronos-startup-probe" t t t))
#+END_SRC

**三重防护（缺一层就会静默降级）**：

| 防护 | 写法 | 挡住什么 |
|---|---|---|
| ① 实例守卫 | =(unless (member (getenv "THOMAS_EMACS_INSTANCE") '("isolated" "pure")) …)= | 隔离子实例（=elisp-test= / =elisp-pure=）里不重复上岗，避免污染验证结论 |
| ② =file-exists-p= | =(when (file-exists-p PATH) …)= | 仓库搬迁 / 改名 / 未 clone 时**不报错也不加载**，但至少你知道「没装」而不是「装了没数据」 |
| ③ =load= 的 NOERROR（第三个参数 =t=）与 MUST-SUFFIX… | =(load PATH t t t)=：NOERROR=**t** 是「找不到不报错」，NOMESSAGE=**t** 是不刷消息 | early-init 期抛错会**打断整个启动**，故必须 NOERROR；代价是**失败完全静默** —— 这正是它需要配合 ② 和排障口诀的原因 |

**探针做了什么**（详见 [[file:architecture.org][docs/architecture.org]]「启动探针（early-init 路径）」）：
从 =early-init= 起挂 =after-load-functions= 按库累计耗时，记 =early-init= / =after-init= /
=startup= 三个锚点；**只写内存，不开库、不建库、不写库**；三条自证收尾路径（=emacs-startup-hook=
的 0 秒 timer / =load-count= 达 800 / =after-init= 后 30 秒兜底）；collect 首次 take 之后由探针
在收尾时**软调用**补写增量。

**不装探针时的降级行为（有意的、可见的）**：

- =startup_phases= 只有 =mode-start= 一个锚点、无 =load:*= 明细（观测器无法观测自己被加载之前的事）；
- 报告「启动分解」节与 Web「启动分解」面板都**如实标注覆盖范围**（「自 mode 启动起 X ms / 总 Y ms」），
  并给出降级文案「（无包加载明细：mode 启动时启动已结束，不记录 after-load-functions）」——**不省略整节**（I11）；
- 其余观测（命令 / 采样 / GC / 资源 / drift / Web）**一律不受影响**。

**硬编码路径的排障口诀**：**=load:*= 为 0 → 先确认 =early-init.el= 里那条路径存在**
（=M-: (file-exists-p "…/el-chronos-startup-probe.el")=），再看 =THOMAS_EMACS_INSTANCE= 守卫是否
跳过了它。仓库改名 / 搬迁后 =(load … t t t)= 会按 NOERROR 语义**静默失败**，不报错、不告警 ——
这是本包**唯一**「装了却没生效且毫无提示」的配置点（见「静默陷阱」⑤）。

> 旧建议（把 =(el-chronos-mode 1)= 整体搬进 =early-init.el=）**不再推荐**：它会把采集器全部
> 设施都拖进 early-init（=package.el= 未初始化、主题未加载、部分 face 不存在），风险远大于收益。
> 探针是零依赖 + 只写内存的，搬它比搬 mode 安全得多。搬 mode 的副作用说明仍保留在
> 「启动分解的物理边界」节，供仍在用旧写法的用户参考。

* autoloads 与 use-package 排障

** autoloads 生成（=make autoloads=）

| 项 | 内容 |
|---|---|
| 用途 | 生成 =el-chronos-autoloads.el=：**16 个 interactive 命令**的 =(autoload SYM "定义文件" ...)= 声明，让包**未加载**时 =M-x= 也能直接调用 |
| 产物位置 | 仓库根 =el-chronos-autoloads.el=（约 221 行，随命令增删变化） |
| 为何不入库 | 生成物与源码必然漂移，入库就得每次改源码后重新生成并提交；=.gitignore= 已显式忽略该文件 |
| 为何不进 L1/L2 | Makefile 的 =EL_FILES= 用 =find ... -not -name 'el-chronos-autoloads.el'= 排除；若不排除，生成后 =make check-parens= / =make lint= 的检查范围会随生成物变化（等于让门禁跟着生成器行为漂移） |
| 实现分流 | Emacs **29.1+** 用 =loaddefs-generate=（自身产物列入 =EXCLUDED-FILES= 防自引用）；更早版本 =(require 'autoload)= + =make-directory-autoloads=。ERT 用例 =el-chronos-autoload-test-autoloads-file-makes-commands-callable= 用**同源守卫**（=loaddefs-generate= 不存在即 =ert-skip=），不硬编码单一实现 |
| 契约守门 | =test/el-chronos-autoload-test.el=（3 用例）锁住三件事：cookie 覆盖全部 interactive 命令（计数不变量）、生成物让 16 个命令 =autoloadp= 为 =t=、每条 autoload 的库名等于定义文件名 |

#+BEGIN_SRC sh
make autoloads
# 生成结果自检：每条 autoload 都应指向定义文件（而不是包名 el-chronos）
grep -n '^(autoload' el-chronos-autoloads.el
#+END_SRC

=:local-repo= 形态下这段**不需要手写**：straight 的 autoloads 步骤在 build 时把生成物写到
=build-<ver>/el-chronos/el-chronos-autoloads.el= 并在加载包时自动 load（实测：16 条 autoload 全部
注册、=autoloadp= 全 =t=）。手工 =load= 只用于方式 B 这类没有 straight 的场合——此时生成物可能
不存在（不入库），故用 =noerror= 形态：

#+BEGIN_SRC elisp
(load (expand-file-name "el-chronos-autoloads" "/home/thomas/Workspace/el-chronos") nil t)
#+END_SRC

** 静默陷阱（实测 Emacs 31.1 / use-package 2.4.5）

五条都**不报错**，只让配置「看起来写了却没生效」——前四条是 use-package 接入本包最常见的坑，
第五条是启动探针（=early-init.el=）的坑。本节原名「四个静默陷阱」（v4 补第 ⑤ 条）。

| # | 陷阱 | 现象 | 正确写法 / 排查 |
|---|---|---|---|
| ① | =:local-repo= 下游跑 =straight-pull-package= / =straight-checkout-package= | 改的是**你的开发仓本身**（=:local-repo= 就是那个 git 工作树，straight 不复刻副本）：未提交改动会被 pull 合入、被 checkout 置于覆盖风险 | 开发仓有未提交改动时**不要**跑这两条；只想刷新源码用 =M-x straight-rebuild-package RET el-chronos=。若你选择 =:load-path= 而非 =:local-repo=，注意它只能写**字符串字面量**（相对路径在宏展开期按当时 =user-emacs-directory= 固化，sexp / 变量形态让整个 form 展开为 =nil=） |
| ② | 关键字参数形态非法 | 整个 use-package form 展开为 **=nil=**：不报错、不加载，命令全是 void | =M-: (pp (macroexpand-1 '(use-package el-chronos ...)))= 看展开；展开为 =nil= 说明某个关键字形态不合法（实测触发：=:load-path (expand-file-name ...)=、=:autoload (sym "file")=） |
| ③ | =:commands= 与 =:demand t= 同存 | autoload 被**静默抑制**，只剩 require（=:commands= 隐含 defer，=:demand= 在关键字序中位于其后，handler 用 =(plist-get state :demand)= 抑制 autoload 生成） | 需要 autoload 就不要同时写两者；本包因「库名恒为包名」问题本就不用 =:commands= |
| ④ | =:if= / =:when= 想表达「仓库缺失就跳过安装」 | **包不住 =:straight=**：安装调用被生成在 =:if= 之外（=progn= 顶层），条件为假时照样执行，本机表现为目录缺失也会去远端 clone 本仓 | 用 =if= 包住**整个** =use-package=：=if (file-exists-p ...) (use-package ...) (display-warning ...)=。判据形态用 =(macroexpand-1 '(use-package PKG :if nil :straight …))= 自检，返回的 =progn= 里若出现 =straight-use-package= 即命中本陷阱 |
| ⑤ | **启动探针的路径硬编码 + =load= 的 NOERROR 语义**（v4） | =early-init.el= 里 =（load "…/el-chronos-startup-probe" t t t)= 的**绝对路径**在仓库改名 / 搬迁后**静默失败**：不报错、不告警，只是 =startup_phases= 的 =load:*= 明细又变回 **0 条**（其余观测照常工作），表现为「探针装了却好像没装」 | 排障口诀：**=load:*= 为 0 → 先确认 =early-init.el= 里那条路径存在**（=M-: (file-exists-p "…/el-chronos-startup-probe.el")=），再确认 =THOMAS_EMACS_INSTANCE= 守卫没跳过它、=load= 的第三个参数（NOERROR）没把错误吞掉。正确写法见「启动探针的安装（推荐）」节的**三重防护** |

实测展开片段（②③④ 的依据；末两条另附 =:load-path= 旧形态的展开作为对照）：

#+BEGIN_SRC elisp
;; ③ 有 :demand t —— autoload 完全不生成，只剩 require
(progn (require 'el-chronos nil nil))
;; ③ 无 :demand —— 生成 autoload，但库名是包名 el-chronos
(progn (unless (fboundp 'el-chronos-report) (autoload #'el-chronos-report "el-chronos" nil t)))
;; ④ :if 形态 —— straight-use-package 在 progn 顶层，:if 只包住 when（条件为假照样安装）
(progn (straight-use-package '(el-chronos :type git :local-repo "…"))
       (when nil (require 'el-chronos nil nil)))
;; ④ if 包裹形态（正确写法）—— straight-use-package 落在 if 的 then 分支内，条件为假整段不求值
(if (file-exists-p "/home/thomas/Workspace/el-chronos/el-chronos.el")
    (progn (straight-use-package '(el-chronos :type git :local-repo "…"))
           (require 'el-chronos nil nil))
  (display-warning 'chronos "未找到"))
;; 附（旧 :load-path 形态）相对路径 "lisp" → 宏展开期固化
(eval-and-compile (add-to-list 'load-path "/home/thomas/.cache/thomas-emacs-elisp-test/lisp"))
;; 附（旧 :load-path 形态）sexp / 变量形态 → 整个 form 失效
nil
#+END_SRC

第三条的另一半：=:autoload (sym "file")= 的 per-symbol 文件名语法**不存在**——=use-package-core.el=
里 =:autoload= 复用 =:commands= 的 normalizer（只吃符号），直接调 normalizer 报
=use-package: :autoload wants a symbol, or list of symbols=。所以跨文件入口只能走
=:init= 显式 =(autoload SYM "FILE")=，库名必须等于定义文件名。

** =:hook= 无参 toggle 陷阱

=el-chronos-mode= 的无参形态是 **toggle**（=define-minor-mode= 的默认行为），而 hook 是**无参调用**：

- 错：=(add-hook 'emacs-startup-hook #'el-chronos-mode)= —— 每次求值都把模式**反转**（开着就关掉）；
  重复求值（重载配置、多个 hook 位）会来回翻转。
- 对：=(add-hook 'emacs-startup-hook (lambda () (el-chronos-mode 1)))= —— 显式 =1=，幂等。

=use-package= 的 =:hook= 同理：=:hook (emacs-startup . el-chronos-mode)= 展开为
=(add-hook 'emacs-startup-hook #'el-chronos-mode)=，仍是符号形态；要安全就写
=:hook (emacs-startup . (lambda () (el-chronos-mode 1)))=。本包推荐 =:demand t= + =:config= 内挂
lambda（见「方式 C」），不用 =:hook=。

** 排障：=M-x= 提示命令未定义（void-function）

按顺序逐条排除，前一条成立就不用往下：

1. **包装上了没有**：=M-: (locate-library "el-chronos")= 应返回
   =<straight-base-dir>/straight/build-<ver>/el-chronos/el-chronos.el=（软链到开发仓）；
   返回 =nil= 说明 recipe 没生效——用 =:load-path= 形态时则多半是「静默陷阱」的 ②。
2. **autoloads 生成了没有**：=M-: (file-exists-p (expand-file-name "el-chronos-autoloads.el"
   (file-name-directory (locate-library "el-chronos"))))= → =t=。为 =nil= 说明 straight 的
   autoloads 步骤没跑（=:build= 被写成 =(:not autoloads ...)= 就会这样），
   跑 =M-x straight-rebuild-package RET el-chronos= 后重试。
3. **命令是否真是 autoload**：=M-: (autoloadp (symbol-function 'el-chronos-report))= → =t= 表示
   「已声明、首次调用才加载」；=nil= 且 =M-: (fboundp 'el-chronos-report)= 也为 =nil=，就是完全没声明。
4. **库名对不对**：=M-: (nth 1 (symbol-function 'el-chronos-report))= 应是 ="el-chronos-report"=。
   若为 ="el-chronos"=（包名），首次调用会报 =Autoloading file ... failed to define function=
   —— =el-chronos.el= 不 =require= 报告模块与 Web 模块，加载它并不会定义该命令。
5. **版本门槛**：=make autoloads= 在 Emacs **29.1+** 走 =loaddefs-generate=，更低版本回退
   =make-directory-autoloads=（结果等价，只是入口不同）；本包运行本身要求 Emacs **29.1+**（内置 =sqlite=）。

* 阻塞提示（echo area）

心跳检测到主线程阻塞（漂移超过 =el-chronos-block-threshold-ms=，默认 2000 ms）时，
事件**始终**写入 =slow_events=（=kind="block"=）并出现在 =el-chronos-report= 与
Web 页面的阻塞列表里；=el-chronos-collect-notify-blocks= 只控制**要不要提示**：

**两条与提示相关的口径**（v3）：

- 本开关只管 **block 档**。亚秒级的 drift（500–2000 ms，落 =hourly_drift= 小时聚合）**从不发提示**：
  亚秒级不配占用 echo area，且它默认就在报告 / Web 的「阻塞事件」节里可见。
- block 只记**命令外**停转（命令执行时间被 =--finish= 的基线重置切出 gap），因此「某条命令执行
  期间卡了 3 秒」不会产生 block 提示 —— 那条命令自己在「慢命令」里。

| 取值 | 行为 | 适用 |
|---|---|---|
| =nil=（默认） | 完全不提示：不占 echo area，也不写 =*Messages*= | 默认。提示会盖住 minibuffer 候选、打断正在进行的输入与补全 |
| =messages= | =message= 被 =(let ((inhibit-message t)) ...)= 包住：只写 =*Messages*= 历史，不占 echo area | 想事后翻日志、又不想被打断 |
| =t= | 真的在 echo area 显示「el-chronos：主线程阻塞约 N ms（已记录）」 | 调参 / 复现卡顿时需要即时可见 |

「echo area 没出现提示」**不代表没记**——查库最快：

#+BEGIN_SRC sh
sqlite3 -readonly "file:$HOME/.emacs.d/.local/state/chronos/chronos.sqlite?mode=ro" \
  -header -column "select ts, round(duration_ms) dur, context_json from slow_events \
                   where kind='block' order by ts desc limit 20;"
#+END_SRC

（=ts= 是毫秒时间戳，用 =date -d @$((ts/1000))= 换算；=context_json= 里的 =mode= 是
判定时刻的 major-mode，可据此定位当时在哪个 buffer。）

* 命令外停转（drift）与调档指引

**drift 是什么**：主线程在**命令之外**停转 **500–2000 ms** 的按小时聚合（表 =hourly_drift=，
每会话每小时一行：次数 / 累计 / 最坏）。超过 2000 ms 改记 =slow_events(kind='block')= 明细，
两档互斥。**命令内**的停转不进 drift —— 它在 =commands= 里有精确 =duration_ms=，
两表**不可相加、也不该相加**（不相交集合：命令间隙的停转 vs 命令总耗时）。

**两个相关 defcustom**（硬约束：drift 阈值必须 **小于** block 阈值、且**大于**心跳间隔 × 1000）：

| 变量 | 默认 | 含义 | 调档含义 |
|---|---|---|---|
| =el-chronos-drift-threshold-ms= | =500= | drift 档最低记录阈值（毫秒） | 上调 → drift 变少、只剩更明显的停顿；下调 → 更灵敏但小时行更密（更「噪」） |
| =el-chronos-block-threshold-ms= | =2000= | block 档（明细）阈值 | 一般不动；drift 阈值必须低于它 |
| =el-chronos-heartbeat-seconds= | =0.25= | 心跳间隔 | 决定两档的**高估上界**（= 一个间隔）与 drift 的检出下界（= 阈值 − 一个间隔） |

**调档指引（可执行）**：

1. **上线先跑一周再动**（默认值不动）。真实频率未知：batch 只能注入人造延迟，量不出真实
   工作负载下 500 ms–2 s 停转的发生率，因此 500 ms 是估计值，不是实测最优。
2. 观察期结束后看两个数：`select sum(count), max(max_ms) from hourly_drift;`。
   - 每小时行数与次数**过多**、噪声感强 → 把 =el-chronos-drift-threshold-ms= 上调到 **800–1000**；
   - 想看见 0.3–0.5 s 的卡顿 → 下调到 **300**，但**不要低于心跳间隔**（=250=）：
     `阈值 < 250` 时每一次正常心跳间隔都可能被判成 drift，只会把噪声灌进库。
3. 觉得自己机器上 timer 唤醒开销明显（笔记本电池、低功耗设备）→ 把
   =el-chronos-heartbeat-seconds= 回调到 **0.5**：开销约减半，但 block / drift 的**高估上界升到
   500 ms**、drift 检出下界相应上移。
4. 代码里**不做断言**（运行中可改），所以上面两条硬约束由你自己遵守。

#+BEGIN_SRC elisp
;; 想更灵敏：只记命令外 ≥300 ms 的停转（心跳仍 250ms，勿低于它）
(setq el-chronos-drift-threshold-ms 300)
;; 觉得太吵：只记 ≥1 s 的命令外停转
(setq el-chronos-drift-threshold-ms 1000)
;; 低功耗设备：把心跳拉回 500ms（高估上界随之升到 500ms）
(setq el-chronos-heartbeat-seconds 0.5)
#+END_SRC

**250ms 心跳的开销**：实测相对开销 **+0.0357%**（[[file:architecture.org][docs/architecture.org]]
「实测结论 13」；噪声地板 ±0.0003% 的 119 倍，距 0.5% 预算余 14 倍）。**但该数字是在
=emacs -Q --batch= 下测的：GUI 主循环未实测**（batch 无 redisplay、无输入事件队列，唤醒路径更短），
只能作为**上界估计**使用；GUI 侧若观感异常就按上面的第 3 条回调。

* 资源采集的开关与口径（v4）

** 开关

=el-chronos-resource-sampling=（默认 **=t=**，即**默认开启**）。设为 =nil= 时**完全不采**：
=--collect-resources= 直接返回，连 =process-attributes= 都不调用（零开销），=hourly_resources=
不再产生新行（**历史行保留**，仍可在报告 / Web 里查）。

** 采什么、从哪来

| 指标 | 取数 API | 落库列 |
|---|---|---|
| 进程 CPU 时间 | =(process-attributes (emacs-pid))= 的 =time=（**cons**，=(HIGH LOW USEC)=），本窗口**差分** | =cpu_ms=（毫秒，累加） |
| 墙钟时间 | =(float-time)= 差 | =wall_ms=（毫秒，累加） |
| 常驻内存 RSS | 同上的 =rss=（单位 **KB**） | =rss_kb_max=（峰值）/ =rss_kb_sum=（累加） |
| 线程数 | 同上的 =thcount= | =threads_max=（峰值） |
| 系统负载 1 / 5 / 15 | =(load-average t)=（**必须传 =t=** 才返回三元列表） | =load1_sum= / =load5_sum= / =load15_sum=（累加）+ =load_n=（样本条数） |

四条实现约束（改代码前必读，详见 [[file:architecture.org][docs/architecture.org]]「路径 7」）：

- **复用既有 10 秒采样 timer，不新增 timer**（唤醒成本 87 µs/次远大于回调本身）；
- **TRAMP 守卫**：整段取数包在 =(let ((default-directory temporary-file-directory)) …)= ——
  =process-attributes= 在 remote =default-directory= 下会把 PID 当**远端主机**的进程；
- **逐字段降级**：任一项取不到 → 落 NULL 并保旧值，**绝不用 0 冒充**；
- **首窗口只建基线**（=time= 是启动至今的累计值）。

** CPU% 的定义**

=CPU% = SUM(cpu_ms) / SUM(wall_ms) × 100=（按小时桶或按窗口汇总）。
**不能**先算每个窗口的 =cpu_ms / wall_ms= 再取平均 —— 各桶 / 各窗口的分母不同，平均会给出错的数。
存的是**两个原始增量**，比值一律在查询层算（SQL 示例见 [[file:schema.org][docs/schema.org]]「查询 4」）。

** 均值分母是 =load_n=，不是窗口数**

- RSS 均值 = =rss_kb_sum / load_n=；负载均值 = =loadN_sum / load_n=。
- =load_n= 是**成功取到 =load-average= 的窗口数**（每次采样三值同时到达，一条样本记 1）。
- =load_n = 0 时均值是 **NULL → 报告与 Web 渲染 =-=（不是 0）**：0 的含义是「观测到了，值为 0」，
  与「没有样本」是两件事（I11 不做「0 负载」的假象）。
- **已知后果**：负载采集全部失败的时段，**RSS 均值同样为 NULL**（分母共用）。这是刻意的诚实降级；
  独立 =rss_n= 列见技术债。

** 明确不采系统内存**

=memory-info= 给的是**整机**内存（=TOTAL-RAM FREE-RAM TOTAL-SWAP FREE-SWAP=），而且在 remote
=default-directory= 下查的是**远端主机**；与「Emacs 进程自己占多少」不是一回事。要判断
「是不是越用越胖」请看 RSS（=rss_kb_*=）与堆大小（=hourly_gc.heap_bytes=，仅 Emacs 31.1+）。

** 为什么不用 =pcpu=**

=pcpu= 是「进程**启动至今**的累计百分比」。本表按小时桶累积、跨小时与跨天对比，累计百分比会把
早期的高 CPU（例如启动期编译）**永久摊进后续每个窗口**，一次高峰之后整天的曲线都抬不起来。
增量差分（=time=）没有这种记忆效应，除以 =wall_ms= 后在诊断上等价。

** 想少一点开销**

设 =el-chronos-resource-sampling= 为 =nil= 即可（整段不执行）。**不要**为此调
=el-chronos-sample-window-seconds= —— 那会同时改变 CPU 采样频率与 GC 采集间距。

* 启动分解的物理边界（重要：不是 bug）

**观测器无法观测自己被加载之前发生的事。**

- 若用 =emacs-startup-hook=（或任何**启动结束之后**的时机）开启 mode —— 本机 =thomas-emacs= 就是
  =(add-hook 'emacs-startup-hook #'el-chronos-mode)= —— 启动分解**只含 =mode-start= 一个锚点、
  没有任何包加载明细**。这是物理边界，不是 bug，也不是采集失败。
- 事实依据：=startup.el= 第 1707 行先 =(setq after-init-time (current-time))=、第 1708 行才
  =(run-hooks 'after-init-hook)=，两行都在 init 文件加载**之后**执行。所以 =collect-start= 执行时
  启动已经收尾，采集器**故意一个启动钩子都不挂**（否则此后你每次 =require= / 打开文件触发的 load
  都会被记成「启动期 load」，把交互期的加载混进启动耗时里，比缺数据更糟）。
- **推荐做法：装 =early-init= 启动探针**（零依赖、只写内存），它从 =early-init= 起就覆盖完整加载，
  且不影响其他初始化代码 —— 见「启动探针的安装（推荐）」节。
- **旧做法：把 =(el-chronos-mode 1)= 提前到 =early-init.el=**（例如 =early-init.el= 末尾）：

#+BEGIN_SRC elisp
;; ~/.emacs.d/early-init.el 末尾
(require 'el-chronos)
(el-chronos-mode 1)
#+END_SRC

  此时 =mode-start= 就是「记录起点」，之后的 load 才会进 =startup_phases=。副作用要知道：
  early-init 期间很多设施尚未就绪（=package.el= 未初始化、主题未加载、部分 face 不存在），
  采集器自身必须能降级——项目已按此设计（采集路径全部 =condition-case= 包裹，I6），
  但你的**其他**初始化代码若也搬进 early-init 需自行确认顺序。
- 无论哪种写法，节标题都会如实标注覆盖范围（「自 mode 启动起 X ms / 总 Y ms」），
  **不会**把近似数据冒充全程；包加载耗时本身也是**近似归因**（相邻 =after-load-functions=
  回调的时间差，含前一个文件的收尾）。

* 卸载

三步，顺序不能反（先停观测再删数据，否则会有未 flush 缓冲写回）。

1. **停止观测**： =(el-chronos-mode -1)= —— 清理 timer、hook（含每 buffer 的局部 hook）、
   profiler、未 flush 缓冲（I5 零残留）。确认：=M-: el-chronos--running-p= → =nil=。
2. **移除加载路径**：删掉配置里的 straight recipe（=:local-repo= 软链随之消失，留下
   =<straight-base-dir>/straight/{repos,build-<ver>}/el-chronos= 时用 =M-x straight-remove-package
   RET el-chronos= 清理），或删掉 =(require 'el-chronos)= 与 =load-path= 条目；
   （可选）删除本地 clone。
3. **删除数据**（可选）：删
   =<user-emacs-directory>/.local/state/chronos/chronos.sqlite=（连同同目录的
   =chronos.sqlite-wal= / =chronos.sqlite-shm=）。删除前请先做完第 1 步。

#+BEGIN_SRC sh
# 卸载后彻底清数据（先确认 Emacs 已退出或已 el-chronos-mode -1）
rm -f ~/.emacs.d/.local/state/chronos/chronos.sqlite*
#+END_SRC

不删库也不影响其他功能：下次重新启用会复用同一库继续累积。

若你用过 =make autoloads=，顺手删掉仓库根的 =el-chronos-autoloads.el=：它是生成物、
**不在版本控制内**，删掉后需要时再 =make autoloads= 重建即可。

* 数据清理

| 操作 | 入口 | 作用范围 | 备注 |
|---|---|---|---|
| 自动 retention | **仅在 =el-chronos-store-open= 时执行一次**（不挂周期 timer；1 小时节流只作用于同进程反复 open / close） | 仅 =commands= / =slow_events=，按 =el-chronos-retention-days=（默认 30 天） | 七张 =hourly_*= 聚合表与两张会话级表（=startup_phases= / =session_meta=）**永久保留**，不参与自动清理。**改 =el-chronos-retention-days= 或想让过期行被清掉，都要等实例重启**（见本节后「保留策略的实际生效依赖实例重启」）；两表都没有过期候选时**完全不开写事务**（候选预检） |
| 按日期 purge | =M-x el-chronos-purge=（交互输入 =YYYY-MM-DD=） | 该日期之前的**全部**数据（含七张 =hourly_*= 与两张会话级表） | 输入留空 = 清空全部 **13 张表** |
| 全部 purge | =M-x el-chronos-purge= 后直接回车 | 清空 13 张表 | purge 会顺带补建当前会话行，避免后续写入撞外键（并把它重建行的 =startup_ms= 置 NULL） |
| 回收空间 | =M-x el-chronos-store-vacuum= | =VACUUM=（重写库文件） | 不能在事务内执行；purge 后跑一次可显著缩小文件 |
| 直接删文件 | 关闭 Emacs 后 =rm chronos.sqlite*= | 全部 | 下次启动自动重建空库（=user_version= 5、13 表 + 3 索引） |

#+BEGIN_SRC elisp
(el-chronos-purge (truncate (* 1000 (float-time (date-to-time "2026-09-01 00:00:00")))))
;; => (("commands" . 12345) ("slow_events" . 67) ("hourly_functions" . 890) ...)
(el-chronos-store-vacuum)   ; => t
#+END_SRC

** 保留策略的实际生效依赖实例重启

自动 retention（=el-chronos-store--prune=）**只在 =el-chronos-store-open= 里调用一次**，不挂
flush timer、也没有任何周期 timer —— 因此：

- 改 =el-chronos-retention-days= 之后，要**下次启动**（或重开库）才按新值清理；常驻一整天不重启
  的实例不会中途清理。**不要**把它读成「1 小时 + 5 秒后生效」：那个 5 秒是 flush 周期，与 retention
  无关；=el-chronos-store--prune-interval-seconds=（3600 s）节流的是「**同进程**反复 open / close」，
  跨进程各自计时（多实例同时启动时「首次各自执行一次」）。
- 想让过期数据立即消失，用 =M-x el-chronos-purge=（交互输入日期）或手动 =DELETE=，不要指望等。
- 每次 open 都会先做**候选预检**（对 =commands= / =slow_events= 各一次 =SELECT count(*)=，
  走时间索引、WAL 下读锁不阻塞写者）；两表都没有过期行就**完全不开写事务** —— 故「反复 open
  但没有过期数据」不再产生空转写事务，也就不是锁竞争源。

** 何时该 purge

- 库文件明显膨胀（例如开了 =el-chronos-usage-granularity= 为 =file= 一段时间后改回 =command=，
  旧的路径类 =hourly_usage= 行不会被自动清掉——该表永久保留）。
- 换了机器 / 换了工作场景，旧数据的趋势对比已无意义。
- 怀疑数据被污染（例如长时间未联网机器时钟跳变导致的桶错位）。

* 排障

| 症状 | 可能原因 | 处置 |
|---|---|---|
| 启动即告警「SQLite 不可用」，采集被禁用 | Emacs < 29 或编译时缺 sqlite | =M-: (and (fboundp 'sqlite-open) (sqlite-available-p))=；换带 SQLite 支持的 Emacs 构建；观测器本身不阻断 Emacs 启动 |
| =el-chronos-web-start= 抛 =user-error=「端口被占用」 | 8787 已被占用（可能是别的实例或 Windows 侧进程） | =ss -lntH "sport = :8787"= 查监听者；改 =el-chronos-web-port= 后重试。**不自动换端口**是设计（I11：可见失败优于静默漂移） |
| 热点函数里一堆 =unknown= 包 | 函数来自**已删除包的残留 =.eln=**、=eval= 即时定义的临时 snippet（=.yas-setup-*=），或 =symbol-file= 确实取不到源码 | native-comp 的 =.eln= 路径已能反查源码（TD-1 已关闭，实测 96.6% 反查成功），故 =unknown= 现在**只剩这两类边界**。看 =el-chronos-attrib-file= 对该符号的返回值：返回 =.eln= 路径说明反查失败（多半是包已删）；不影响其他统计。需要源码级结论时用 =el-chronos-profile-command= 对单条命令剖析 |
| 采样数一直是 0 / 热点表空 | ① 采样器启动失败（=display-warning=）；② 观测期间**没有真实操作**——纯 =sleep= 不产生 CPU 样本 | ① 查 =*Messages*= 与 =el-chronos-status=；② 正常敲命令 1 分钟后再看（采样是 CPU 采样，阻塞等待期没有 leaf 样本，阻塞要靠心跳 =slow_events(kind='block')= 体现） |
| DB 体积显示得比预期小 | =el-chronos-analysis-db-size= **只统计主文件**，不含 =-wal= / =-shm=；WAL 未 checkpoint 时数据还在 wal 里 | 看总占用：=ls -l ~/.emacs.d/.local/state/chronos/=；随 checkpoint 主文件会长上来；需要立刻收敛就跑 =M-x el-chronos-store-vacuum= |
| 某些 buffer 里的命令完全没被计时 | TD-9 类问题（=pre-command-hook= / =post-command-hook= 在 Emacs 31 起 auto-buffer-local） | 已修复：启动时遍历 =buffer-list= 补挂局部 hook 并由 =buffer-list-update-hook= 增量覆盖；若自造 buffer 仍漏采，确认没有在 =kill-all-local-variables= 之后手动覆盖这两个 hook |
| =total_ms= 与内置 =profiler-report= 的 total 列不一致 | 口径不同：本模块 total 按**栈内去重**，内置报告按每帧累加（TD-10） | 不是 bug。占比与回归判定都用 self 口径；跨工具对比时以 self 为准 |
| echo area 不再弹出「主线程阻塞约 N ms」 | =el-chronos-collect-notify-blocks= 默认为 =nil=（静默），**不是漏记**——事件照旧落 =slow_events(kind="block")= 并进报告 / Web 页面 | 查库确认（见「阻塞提示」节的 SQL）；需要即时可见就把该变量设为 =messages=（只进 =*Messages*=）或 =t=（真 echo） |
| 回归列表里出现看起来「没变慢」的函数 | 回归按 =el-chronos-regression-window-days=（默认 7 天）与自身上下窗口比较，**与页面显示范围无关**；小样本噪声由 =el-chronos-regression-min-samples= 抑制 | 看返回里的 =:current-samples= / =:previous-samples=；嫌噪就提高阈值或最小样本数 |
| 包占比里 =built-in= 占大头（甚至过半） | **正常口径**：Emacs C 原语（=kill-buffer= / =plist-get= / =redisplay_internal= 等）与 GC 采样本就来自内核，2026-10-25 起归 =built-in= 而非 =unknown= | 无需处理；若想看用户配置的开销，按包名过滤掉 =built-in= / =GC= / =unknown= 三行即可。历史数据需 =el-chronos-purge= 后重来才是新口径 |
| 采集健康显示「本期无采集数据」 | **不是故障**：采集器还没写过 =hourly_health= 行（=:rows= = 0），例如刚开始用、或这段时间内没有一次 flush 成功过 | 与「本期无采集异常」是两个不同结论：先确认 =el-chronos-mode= 在跑、=M-x el-chronos-status= 能显示库路径，然后等一个 flush 周期（默认 5s）再看。只读 =:ok-p= 会把「没采集」读成「一切正常」，报告与页面都按 =:rows= 先行分支 |

| 命令内卡顿没进 drift（「我明明卡了两秒」） | **设计如此**：drift 与 block 只覆盖**命令之外**的停转，命令执行期间的时间被结算时的基线重置切出 gap | 命令内的停转看「慢命令 TOP」节 / =commands.duration_ms=（≥200 ms 的另有一条 =slow_events(kind='command')=）。**两表不可相加** —— 相加会把同一段时长算两次。见「命令外停转（drift）」节 |
| v3 前后 =slow_events(kind='block')= 的量看起来变少了 | **口径变了，不是采集退化**：v3 之前命令内 ≥2 s 停转会**同时**记 =kind='command'= 与 =kind='block'=（双记，TD-11 ③）；v3 起 block 只记命令外停转，命令内那一条不再产生 | 做跨版本趋势对比时**必须按时间点切开**（升级前后分段统计），否则会把「双记消失」误读成「阻塞变少了」。历史行不迁移、不回改 |
| 慢事件里 =kind='command'= 的 =stack_json= 全是 NULL | **v4 起的有意为之**：结算时命令帧已弹出，原先记的全是采集器**自身帧**（无信息量），故改为写 NULL | 命令归属请查同时段的 =hourly_stacks= 样本；不要把 NULL 当采集失败 |
| =make lint= 报 =Defining as dynamic an already lexical var=，但 **exit code 仍是 0** | **工具链坑**：=lint= 目标里 =(let ((byte-compile-dest-file-function …)) (byte-compile …))= 在 **=bytecomp= 未加载**时先按动态绑定编译这些变量名，于是报这条警告；而且字节编译的告警不改变 =emacs --batch= 的退出码 → **会被误判成「零告警」** | 正确写法是**先 =(require 'bytecomp)=** 再 =let= 绑定；判断 lint 是否真通过要看**输出里有没有告警行**，不能只看 exit code（=make lint= 的实现已按「有告警即失败」处理，自己写脚本时注意别踩） |

** 多实例共享库是设计意图，不是配置错误

同一 =user-emacs-directory= 下的多个 Emacs（GUI 主实例 + daemon + 隔离验证实例 =elisp-test=，
以及偶发的 =emacs -Q --batch= 脚本）会共用同一个 =chronos.sqlite= —— **这是设计意图**：
=sessions= 每会话一行、=sessions.host= 记主机名、=hourly_*= 的主键含 =session_id=，三者的存在
前提就是「一个库、按会话纵向分行」。报告与 Web 因此能一眼看到「今天两个实例各自花了多少」，
不必跨库归并（SQLite 没有跨库 JOIN）。I3 也把「数据只写 =el-chronos-db-path=」定成不变量，
按实例分库正是为此被否决的方案（见 [[file:adr/0007-multi-process-write-concurrency.md][ADR-0007]]）。

代价是 SQLite 的单写者模型：多写者会撞锁。观测器的处置是**自愈**（保留本批 + 退避重试），
不是报错也不是分库 —— 判读见下两节。

** 何时算异常

| 现象 | 判定 | 处置 |
|---|---|---|
| 库里有多个 =sessions= 行、多会话时间并行 | **正常**：每个 Emacs 进程一个会话 | 无需处理；报告 / 页面按会话分行显示，总量看汇总 |
| =hourly_health= 里 =busy-retries= 持续上升，而 =dropped-commands= / =dropped-events= 不动 | **正常**：撞锁被自愈 | 无需处理（这就是并发写处置在工作） |
| 出现「写库连续撞锁 6 次，本批缓冲已按计划丢弃」 | **异常**：数据真的丢了 | 按下一节第 2 档处置 |
| 某实例一整天没有 =commands= 行，但 =el-chronos-status= 显示在跑 | **异常** | 旧版会因 open 期建会话行撞锁而整场不采集（现已改为延迟补建）；仍复现则查 =*Messages*= 的「打开数据库失败」、库文件权限与磁盘空间 |
| 同一会话的 =commands= 与 =hourly_*= 时间范围对不上 | **可能正常**：会话行补建窗口（≈ 5 秒）内聚合被跳过、明细保留 | 见 [[file:architecture.org][docs/architecture.org]]「已知口径损失」（TD-36）；缺口只有几秒，不是整天 |

** database is locked 怎么判（三档）

判据全部来自 =hourly_health= 四个键（=busy-retries= / =flush-failures= / =dropped-commands= /
=dropped-events=）与告警文案，**不需要**打开库手查。先看 =dropped-*= 有没有涨，再决定要不要管：

1. **自愈，无需处理**：=dropped-*= 不涨，只有「写库撞锁（第 N/6 次），明细与聚合保留待下次 flush
   重试」这类**过程**告警（受限流，10 分钟最多一条）。数据没丢，退避 30 秒后自动重试。
   查库确认：
   `select key, sum(value) from hourly_health where key like 'dropped-%' group by key;`
   —— 两行都为 0（或无行）即为自愈。
2. **真丢了，需要查对端在干什么**：出现「写库连续撞锁 6 次，本批缓冲已按计划丢弃」这条**结果**
   告警（绕过节流，一定会出现），或 =dropped-commands= / =dropped-events= 同时上升（条数 = 被
   丢弃的缓冲长度，单类上限 50000）。对端常见原因：大 =prune=（删百万行实测 2.18 s）、schema
   迁移、外部 =sqlite3= 长事务、磁盘 / 文件系统卡顿。处置：确认没有外部进程长期持写锁
   （=fuser -v chronos.sqlite=；看 =*Messages*= 里同时段是否有另一实例在跑 prune / 迁移）。
   **不要**删 =-wal= / =-shm= 文件（未 checkpoint 的数据会一起丢）。
3. **多实例常态，可忽略**：=hourly_health.busy-retries= 持续上升而 =dropped-*= 纹丝不动 ——
   「抢锁、失败、保留、重试成功」的循环，属正常并发读数。

一句话口诀：**看 =dropped-*= 是否跟涨**。=busy-retries= 与 =flush-failures= 在撞锁时会**同时**
上升 1，保留重试与达上限丢弃在它们上面完全一样，故**不能**拿它们当「丢没丢数据」的判据。

** 迁移 / checkpoint / vacuum 的撞锁边界（既有行为，本批不改）

并发写处置只覆盖「flush / prune / purge / 建会话行」四条路径，下面三处仍是**既有行为**，
遇到时按此解释，不要当新 bug：

- **迁移撞锁仍使 =store-open= 返回 nil**：=el-chronos-store--open-db= 内的迁移走启动路径的
  2000 ms 超时（不套写超时包装器）。只在「升级后首次启动 + 对端恰好持写锁」时发生，概率低；
  处理办法是关掉另一个实例后重开，或等它写完再 =M-x el-chronos-mode= 重开。
- **=--migrate= 的 =wal_checkpoint(TRUNCATE)= 会静默跳过**：他人持写锁时该 pragma 失败，被
  =ignore-errors= 吞掉 —— 后果是迁移生成的 =chronos.sqlite.bak= **可能不含最新 WAL 数据**
  （备份点会比预期早一点）。回滚前若在意这点，先确保没有别的实例在跑再迁移。
- **=el-chronos-store-vacuum= 用默认 2000 ms 且不套写超时包装器**：它是手动命令（不是周期路径），
  对端持锁时可能直接失败并给限流告警；重跑一次即可，**没有**「等 8 秒」的优待。

** 多实例共享库：撞锁退避的代价与判读

多个 Emacs 实例共用同一个库时写者之间会撞锁（SQLite 单写者模型）。观测器的处置是
「保留本批 + 短退避后重试」，由此产生三条必须知道的读法：

- **崩溃丢数据窗口从 5 秒放大到 35 秒**：一次 flush 撞锁后本批被保留，并退避
  =el-chronos-store--flush-backoff-seconds=（30 秒）再试，故撞锁期间崩溃最多丢
  「一个 flush 周期（5 s）+ 一个退避窗口（30 s）」。取 30 秒的依据是对端的大 prune /
  迁移实测在 0.5–2.2 秒量级，30 秒足以跨过，又远小于「这软件卡住了」的感知阈值。
  **不要为了缩回 5 秒而取消退避**：不退避会让主线程被「每 5 秒一次、每次等满 8 秒」的
  等锁占满（实测 8 次 × 8.01 s），比丢几秒数据严重得多。
- **过程告警 ≠ 丢数据，结果告警才是**：被限流（10 分钟一条）的是「撞锁（第 N/6 次）」这类
  **过程**消息；「本批缓冲已按计划丢弃」走 =el-chronos-store--warn-force= **不受限流**，出现即
  数据真的丢了。分档判读、查库 SQL 与对端排查见上一节「=database is locked= 怎么判（三档）」。
- **退避只推迟重试，不丢缓冲**：退避期内 flush 直接早退（不碰库、不打 pragma），缓冲、
  聚合 hash 与自监控计数原样保留；下一次允许尝试的时刻由
  =el-chronos-store--flush-backoff-until= 决定（到点自动恢复，无需人工干预）。

* 隐私边界与数据保留

** 记录 / 不记录

| 类别 | 内容 |
|---|---|
| **记录** | 命令名、耗时、GC 耗时、major-mode、项目 **basename**、结果（=ok= / =aborted= / =error=）、函数符号名、函数定义源码路径（仅归因所需）、会话级 =git-head= / =config-sig= 两键（见下「隐私边界补充」） |
| **不记录** | 被操作文件路径、buffer 内容、按键序列、命令参数、剪贴板、环境变量、**配置文件内容**（=config-sig= 只取相对路径 + mtime + size 的 sha1） |

=commands.project= 只存 basename（=file-name-nondirectory= 处理后的目录名），取不到为 =NULL=；
断言：该列不出现 =/=。唯一例外是用户**主动**把 =el-chronos-usage-granularity= 改为 =file=——
此时 =hourly_usage= 会写入被操作文件的绝对路径，且该表永久保留（只能 =el-chronos-purge= 清）。

** 数据保留表

| 表 | 保留 | 清理方式 | 行数上界 |
|---|---|---|---|
| =sessions= | 随 =commands= 一并清理（=started_at= 同口径） | retention / purge | 每启动一次一行 |
| =commands= | =el-chronos-retention-days=（默认 30 天） | 自动 retention / purge | 每命令一行 |
| =slow_events= | 同 =commands= | 自动 retention / purge | 仅超阈值事件 |
| =hourly_functions= | **永久** | 仅 purge | ≤ 24 × 函数数 / 天 |
| =hourly_usage= | **永久** | 仅 purge | ≤ 24 × 维度取值数 / 天 |
| =hourly_stacks= | **永久** | 仅 purge | ≤ 24 × =el-chronos-store-stack-top-n=（默认 200）× 会话数 / 天 |
| =hourly_gc= | **永久**（仅 purge） | 仅 purge | 每会话每小时 ≤ 1 行（与既有 =hourly_*= 同量级，可忽略） |
| =hourly_health= | **永久**（仅 purge） | 仅 purge | 每会话每小时 ≤ 7 行（7 个固定键，只写非零项；同量级，可忽略） |
| =hourly_drift= | **永久**（仅 purge） | 仅 purge（=el-chronos-store--prune= **不碰它**） | 每会话每小时 ≤ 1 行；只在命令外 500–2000ms 停转发生时写入（主键去重 upsert），与 =commands= 的时长**不可相加** |
| =hourly_resources= | **永久**（仅 purge） | 仅 purge（=el-chronos-store--prune= **不碰它**） | 每会话每小时 ≤ 1 行（v4）；只在 10 秒采样 tick 上写入（=el-chronos-resource-sampling= 为 nil 时完全不写）。**只含进程自身的 CPU / RSS / 线程数与系统负载，不含任何用户内容**（不涉 I7） |
| =startup_phases= | 随 =sessions= 由 purge 清理 | 仅 purge | **每会话 ≤ top-N + 3 行**（默认 ≤ 53，=el-chronos-startup-top-n= 为 50；=first-idle= 记录时 ≤ 54）—— 比 =sessions= 高两个量级，**频繁重启的机器上会明显增长，是本项目最值得留意的一张表** |
| =session_meta= | 随 =sessions= 由 purge 清理 | 仅 purge | 每会话 ≤ 2 行（=git-head= / =config-sig=，取不到则不写行） |

** 隐私边界补充：=session_meta= 的两个键

=session_meta= 记录两个会话级标记：

- =git-head=：配置仓库的**提交 sha**（含分支解析：读 =.git/HEAD= → loose ref → =.git/packed-refs=
  回退 → detached 裸 sha；任一步失败即不写行）。
- =config-sig=：配置文件的**指纹**，由 =el-chronos-config-watch-globs=（默认
  ='("early-init.el" "init.el" "lisp/init-*.el")=）展开的每个文件的**相对路径 + mtime + size**
  排序后做 =secure-hash 'sha1= 得到。**不含任何文件内容**。

**这两个键可以识别你的配置仓库状态**（用了哪次提交、配置何时改过），属用户可识别信息：
=el-chronos-purge= **会删除它们**（含当前会话行的 meta），所以「泄露」窗口 = 库里还留着那段历史的时间。
不想留就可以随时 =M-x el-chronos-purge=。若连采集都不想有，把 =el-chronos-config-watch-globs=
设为 =nil=（不匹配任何文件 → 不写 =config-sig= 行）；=git-head= 没有开关，由 purge 负责清理。

** Web 的特殊说明

Web 无鉴权；只绑 =127.0.0.1= 仅防 LAN 暴露，**不构成本机访问控制**（WSL2 mirrored 网络下
Windows 侧进程可直连该端口）。定位是「本机自用的只读视图」：默认不启动，用完即
=M-x el-chronos-web-stop=，不要在不可信本地进程或多用户共享环境里长期开着（TD-6）。
