** 只读与 loopback 边界

- 只绑 =127.0.0.1=（=el-chronos-web--host= 是常量，不接受 =0.0.0.0=），端口 =el-chronos-web-port=（默认 8787）。
- **无鉴权**。loopback 只防 LAN 暴露，**不构成本机访问控制**：WSL2 mirrored 网络共享端口空间，
  Windows 侧进程可直接访问该端口（I8，见 [[file:../Readme.org][Readme]]「隐私边界」）。
- 默认不自动启动（=el-chronos-web-auto-start= 为 nil）；端口占用 → =user-error=，
  **不自动换端口**（I11）。用完 =M-x el-chronos-web-stop= 释放端口。
- 端口 =0= 时由内核分配：=el-chronos-web-start= 的 =message= 与 =user-error= 一律取
  =(process-contact PROC :service)= 反映**实际绑定**端口（取不到才回落入参），因此传 =0= 也不会
  提示「http://127.0.0.1:0/」。调用方可用 =(process-contact (el-chronos-web-start))= 核验。
- 路由表无写入 / 执行入口；CSV 导出也是只读查询 + 格式化。

** 浏览器自动打开（=el-chronos-web-open-browser=，v4）

| 场景 | 行为 |
|---|---|
| =M-x el-chronos-web-start=（**交互式**） | =el-chronos-web-open-browser= 为 =t=（默认）→ 启动后用 =browse-url= 打开页面；=nil= → 只在 echo area 显示 URL |
| 程序化启动（=el-chronos-web-auto-start= 在启用观测时顺带起 server） | **绝不弹浏览器**：判据是「开关为真 **且** =called-interactively-p= 为真」，两条缺一不可，否则每次启动 Emacs 都会弹窗 |
| =M-x el-chronos-web-browse=（v4） | 打开（未启动则**先启动**）页面；**不看** =el-chronos-web-open-browser= —— 该命令本身就是用户显式要求打开。未启动时先走 =el-chronos-web-start= 的**非交互**路径（天然不弹），随后由本命令打开一次，**不会双弹**。server 已运行时它每次都打开当前页面，而 =web-start= 在已运行时不打开 |
| =browse-url= 失败 | 只 =message= 提示并给出 URL，**不影响已启动的 server**（I11：可见降级，不静默、不中断、不 =user-error=） |
| =el-chronos-web-port= 为 0 | URL 取 =(process-contact PROC :service)= 的**实际绑定**端口，不会出现 =http://127.0.0.1:0/= |

** 单线程串行处理的含义

- 请求处理在 **Emacs 主线程同步执行**：=:filter= 收字节 → 凑到 =\r\n\r\n= → 解析请求行 → 一次响应
  → =Connection: close= + EOF 关闭。因此**不需要** keep-alive、分块传输、长连接超时管理。
- 后果一：响应时间 = 查询时间（SQLite 本地读取，毫秒级）；并发请求在 Emacs 里**排队**，
  不是并行——多个标签页同时刷新会串行处理。
- 后果二：单个慢查询会占住主线程（进而让采集的 timer 延迟）。因此列表接口都有 =limit= 上限
  （默认 20、最大 1000），堆栈默认 50，包占比不分页。
- 后果三：单请求累积上限 16KB（=--max-request-bytes=），超出返回 413，防畸形请求无限占内存。
- 单请求异常 → 500 且 server 继续服务（I11：不因一次坏请求整体挂掉）。
  **500 不回显内部错误**：浏览器只看到通用文案「请求处理失败。内部错误详见 Emacs 的 =*Messages*=。」，
  错误详情（常含绝对路径与 SQL 片段）经 =display-warning= 写到 Emacs 侧 =\*Messages\*=
  / =\*Warnings\*=，本机用户仍能排障——可见降级但不向浏览器泄露实现细节。

** 「GC 归因」节的标题与首行为什么必须带限定语（v5）

节标题是 **「GC 归因（发生在哪条命令之后）」**，正文首行固定为
=本表回答「GC 发生在哪条命令之后」，不是「哪条命令导致 GC」；在 idle / 进程过滤器里
this-command 为上一条命令。= —— 这两处限定**不可删改**：归因键是 GC 时刻的
=this-command= × =major-mode=，在 idle timer / 进程过滤器 / redisplay 里 =this-command=
仍是上一条命令（滞后），启动期与 batch 下是 ="<none>"=。缺了限定，读者会把「save-buffer
之后发生了 6 次 GC」读成「save-buffer 导致 6 次 GC」。

配套的两条口径：① =hour_ts= 是 **flush 时刻**的整点，不是 GC 发生时刻（跨小时误差 ≤1 个
采样窗口）；② =sum(hourly_gc_attrib.gc_count) ≤ hourly_gc.gc_count=，差值 = hook 安装前 /
采集窗口外的 GC，**只能比大小、禁做等式校验**。因此本节紧接「GC 与内存」之后 —— 总量与
归因必须相邻才能对照阅读。

** 「热点函数」节内的「栈包含占比 TOP」子小节（v4，**不增节**）

=el-chronos-analysis-inclusive-functions= 的结果以 =** 栈包含占比 TOP= 的形式挂在「热点函数」节内，
**不新开节**：它回答的是与「热点函数」同一个问题（谁在耗 CPU）的另一个口径 —— self 口径把成本
记在被调用的 built-in 帧上，会把调用者严重低估；包含口径按「出现在多少比例的采样栈里」计。
两个口径并排看才完整，拆成两节反而要读者来回对照。每项：函数 / 包 / 包含样本数 / 占比 / 涉及栈数。

** 「阻塞事件」节内的 drift 汇总行（v3）

**节数现为 16（v4 新增「资源」节、v5 新增「GC 归因」节），但 drift 汇总仍**刻意不新增节**：drift 与 block 同属
「命令之外的停转」，只有放在一起读者才看得到完整图景（drift 覆盖 [500ms, 2000ms) 区间，
block 覆盖 ≥2000ms）。抽成独立节会让「命令外停转」被拆到两处，还得连带改一堆按节数断言的
老用例。

这一行由 =el-chronos-report--drift-line= 生成，两种文案（与 =el-chronos-report.el= 的实现逐字一致）：

- 有数据：=- 命令外停转（500–2000 ms）：本期 37 次，累计 24.10 s，最坏 1.82 s（累计与最坏为高估值，每次最多多算一个心跳间隔 250 ms；命令内停转见「慢命令」节，两者不可相加）=
- 无数据（I11 可见降级，**不留空白**）：=- 命令外停转（500–2000 ms）：本期无记录（命令内停转见「慢命令」节；两者不可相加）=
- 即使下方的 block 明细表降级为 =（无数据）=，这一行也照样出现。

**口径必须在文案里出现**（不可删改的三处）：① 带「**命令外**」限定；② 标注**高估值**（单次时长
以「发现时距上次心跳基线的间隔」计时，每次最多多算一个心跳间隔）；③ 无数据时也给「命令内停转
见「慢命令」」的指引。区间上下界分别取 =el-chronos-drift-threshold-ms= 与
=el-chronos-block-threshold-ms=、高估上界取 =el-chronos-heartbeat-seconds= 换算的毫秒 ——
三个都是可调 defcustom，**写死会与实际判定脱节**。

** 各节的降级文案（I11：任何情况都不省略整节）

| 节 | 触发条件 | 降级文案（与 =el-chronos-report.el= 的常量逐字一致） |
|---|---|---|
| GC 与内存 | 无桶数据，或全部桶的 =gc-count= / =gc-ms= 都是 0（会话首窗口只建基线） | =--gc-degrade=：「本期无 GC 采样数据（Emacs 31.1 以下不采集堆大小）。」整节不省略 |
| GC 归因（发生在哪条命令之后） | =hourly_gc_attrib= 无行（schema v5 起才采集；老库、刚升级、本次会话尚未跨过一个 flush 窗口） | =--gc-attrib-degrade=：「尚无 GC 归因数据（schema v5 起采集，需运行一段时间）。」整节不省略；首行的语义限定**照常出现**（降级时也要读者知道这张表本来回答什么问题） |
| 资源（CPU / 内存 / 负载） | 无 =hourly_resources= 行（=:samples= 为 0 / 查询失败），或用户关了 =el-chronos-resource-sampling= | =--resource-degrade=：「本期无进程资源数据（=hourly_resources= 为空；=el-chronos-resource-sampling= 关闭时不采集）。」整节不省略；**两条成因都是真的**（资源采样默认**开启**，用户可关闭） |
| 资源（CPU / 内存 / 负载） | 有数据但部分桶 =load_n= 为 0 | CPU% / RSS 峰值照常显示；=RSS 均值= / =负载 1m= 渲染 =−=（**不是 0**，0 表示「观测到 0」）。口径注写在节内 =--resource-caveats= |
| 启动分解 | 无任何启动数据（=:session-id= 为 nil） | 节标题退化为「启动分解」，正文 =--startup-degrade=：「本期无启动分解数据（需在启动结束前启用 =el-chronos-mode=，最早可在 early-init.el 里启用）。」**整节不省略** |
| 启动分解 | 有 =startup_phases= 但缺 =startup_ms= | 标题里「总 Y ms」显示 =−=，正文补 =--startup-total-degrade=：「（无总启动耗时：该会话的 startup_ms 尚未写入）」 |
| 启动分解 | 无阶段锚点 | =--startup-phases-degrade=：「（无阶段锚点：mode 启动时启动已结束，只能记录 mode-start 之后的阶段）」 |
| 启动分解 | 无包加载明细 | =--startup-loads-degrade=：「（无包加载明细：mode 启动时启动已结束，不记录 after-load-functions）」 |
| 采集健康 | =:rows= 为 0（本期没有 health 行） | 「本期无采集数据（采集器尚未写入健康指标）」——**不许**落到 =:ok-p= 分支（analysis 无数据时同样给 =:ok-p= 为 t，照抄会把「没采集」读成「一切正常」） |
| 采集健康 | =:rows= > 0 且 =:ok-p= 为 t | 只给一行「本期无采集异常（flush N 次，平均 X）」——「无异常」不等于「无信息」，flush 次数与均值是正常运转的度量 |
| 采集健康 | 查询失败（analysis 返回 nil） | 空表 + =（无数据）= |
| 配置变更 | =:sessions= 为空或查询失败 | =--config-degrade=：「本期无会话变更记录（会话启动时未取到 git-head / config-sig，或窗口内没有会话）。」整节不省略 |

口径提醒：启动分解节的**包加载耗时是近似归因**（相邻 =after-load-functions= 回调的时间差），
且**只覆盖 mode 启动之后**的 load —— 节标题必须如实标注覆盖范围，不许把近似数据冒充全程
（物理边界与「怎么才能覆盖完整启动」见 [[file:operations.org][docs/operations.org]]「启动分解的物理边界」）。

* 性能注意

| 项 | 取值 | 控制手段 |
|---|---|---|
| Web 列表分页 | 前端每页 10 行（状态对象 =per=） | 单页行数固定，避免一次把全部排行塞进 DOM |

| Web 资源端点（v4） | =/api/resources= 的响应体实测 **139 956 字节**（≈137 KB；30d 窗口、720 小时每小时 1 行 → **720 个 1 小时桶** × 每桶 11 字段；fixture 为 720 个整点行、每小时 cpu 1 s / wall 10 s / RSS 512 MB / 12 线程 / 负载 2.5-2.0-1.8，2026-10-26 本机 =emacs -Q --batch= 实测）。同一 fixture 下 1d / 7d 默认实测 **4 928 / 32 867 字节**。**口径已变**：修复桶宽 off-by-one 之前，同一 fixture 的 30d 只有 360 个 **2 小时**桶、70 308 字节 —— 现在是它的约 2 倍（720 桶 / 1 小时桶宽） | 桶数用 =buckets= 参数调小：30d 下传 24 实测 5 558 字节（25 桶、30 小时桶宽）、传 168 实测 28 391 字节（145 桶、5 小时桶宽）。137 KB 在单线程串行下序列化 + 传输仍是毫秒级，但仍比修复前翻了一倍：**自动刷新 30s 时每轮都要重查 720 个整点行并序列化这个体量**，页面长时间开着且停在 30d 时会持续占用主线程时间片——数据量大时把 =buckets= 调小，或改用 =/api/resources?range=7d= |
| org 报告 | 慢命令 / 热点函数 / 阻塞 / 回归 / 会话各 20 行；趋势最近 48 桶；栈 10 行 | 报告一次成型、无增量渲染；重查询期间抑制阻塞判定，避免把报告耗时记成假阻塞 |
