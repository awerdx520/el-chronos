* 三形态总览

| 形态 | 入口 | 产物 | 定位 | 依赖 |
|---|---|---|---|---|
| org 报告 | =M-x el-chronos-report= / =el-chronos-weekly-report= | =*el-chronos-report*= buffer / org 文件 | 归档、版本间 diff、导出 CSV/JSON | 零第三方 |
| Emacs 内页面 | =M-x el-chronos-dashboard= | =*el-chronos*= buffer（ETAF 挂载） | 日常顺手看一眼、快捷键切范围、行级下钻 | 软依赖 =etaf= + =etaf-ui= |
| 浏览器 Web dashboard | =M-x el-chronos-web-start= | =http://127.0.0.1:8787/= | 深度分析：多图表、搜索排序分页、火焰图、多会话对比 | 零第三方（内置 =make-network-process=） |

共同约束：

- **只读**：三者都只查库。Web 路由表里没有任何写入 / 执行入口（I8）。
- **数据同源**：数字必然一致，不存在「两边对不上」；新增一种形态不需要改采集与存储。
- **降级可见**（I11）：ETAF 缺失 → =tabulated-list= 简版；terminal frame → 文本字符图；
  端口占用 → =user-error= 且不换端口。任何一种失败都不影响采集与其他形态。

** 主题与配色（跟随当前 Emacs 主题）

页面**不使用固定配色**：所有颜色来自「当前 Emacs 主题」的两条通道，界面在深色 / 浅色主题
下自动换色（实测 2026-10-24，Emacs 31.1，ETAF 已装）。

| 通道 | 实现 | 覆盖范围 | 依据 |
|---|---|---|---|
| ① ETAF Theme（主通道） | 根组件 =:setup= 调 =(etaf-theme-provide (--theme-palette))= | 面板、按钮、表格边框、文字色等**所有内置组件**的语义 token | =etaf-ui= 每个组件都从继承的 Theme 取 =:ui-panel-bg= / =:ui-fg= / =:ui-table-border= 等 token，取不到才回落到包内固定浅色调色板（=#FFFDF8= 等） |
| ② 根节点属性 + face remap | 根 =column= 带 =:background-color (--theme-background)= / =:color (--theme-foreground)=；挂载后 =--apply-theme-canvas= 调 =face-remap-set-base 'default= | 面板之外的行尾空白、buffer 未被文字覆盖的列、默认文字色 | =etaf-mount= **只接受** =:viewport-width= / =:viewport-height= / =:observer=，没有 =:background= / =:foreground=；=etaf-app-open= 虽有这两个参数，但它自带 buffer / 窗口 / 模式行整套语义，与本页面的挂载方式不兼容 |

=--theme-palette= 的取值映射（全部经 =face-attribute … nil t= 读，主题未定义则跳过该键）：

| ETAF token | 取自 |
|---|---|
| =:ui-bg= / =:ui-fg= | =default= face 的 :background / :foreground |
| =:ui-panel-bg= | =default= 背景往对比方向偏移 4（=color-darken-name= / =color-lighten-name=，按 =background-mode=） |
| =:ui-panel-fg= / =:ui-button-ghost-fg= | =default= 前景 |
| =:ui-panel-border= / =:ui-border= / =:ui-table-border= | 优先 =shadow= 前景，其次 =mode-line= 背景，最后 =default= 前景 |
| =:ui-muted-fg= | =shadow= 前景 |
| =:ui-accent= / =:ui-button-secondary-fg= / =:ui-info-fg= | =link= 前景 |
| =:ui-button-primary-bg= | =highlight= 背景（缺省回落到 accent） |
| =:ui-success-fg= / =:ui-warning-fg= / =:ui-danger-fg= | =success= / =warning= / =error= face 前景 |

约束（都是踩过坑的）：

- **只放解析出颜色串的键**：给某个 token 一个 =nil= 值会让组件把 nil 当颜色用，渲染期报非法颜色；
  缺键时 ETAF 自动回落到包内默认调色板。
- **=unspecified-bg= / =unspecified-fg= 必须过滤掉**：=emacs -Q --batch= 的 =default= face 就是这两个值，
  直接传下去等于把垃圾当颜色。
- 主题切换后重绘即可（=g=）；颜色在**渲染期**读取，不需要重启页面。

** 宽度策略与不截断（卡片布局）

两条目标互相拉扯：**不溢出**（任何节点不越过窗口右边界）与**不截断**（命令名 / 函数名 /
包名 / 路径必须完整可见）。ETAF 表格做不到后者，故数据区改用卡片。

=etaf-table= 为什么不行（读 =etaf-ui-table.el= + 实测复核）：

| 列宽语义 | 对齐 | 超长单元格 | 结论 |
|---|---|---|---|
| 整数 N（=:width 30=） | 严格对齐（走「定宽文本」快路径，整行一个 padded Text Host） | =etaf-ui--table-fit-text= 调 =truncate-string-to-width= 补 =…= | 违反「不截断」 |
| =(fr N)= 权重 | **不对齐**：每行各自算 track（行容器 shrink-wrap），表头与数据行、数据行彼此起始位置都不同 | =etaf-ui--table-cell= 固定 =:overflow hidden :wrap-mode none=，直接裁掉（连 =…= 都没有） | 两罪并罚 |
| =(fr N)= + 单元格自定义 =:cell= 返回 =:min-width (px 0)= 的可换行 box | 仍不对齐（min-width 压不住 grid 的 min-content 差异） | 文本能换行（=wrap-mode word= 生效），行高自适应 | 可换行但列不对齐 |

当前实现（=--card= + =el-chronos-dashboard-card=）：

- 每条记录一张卡片：第一行**主键全文本**（命令名 / 函数名 / 阻塞事件的命令；会话用启动时间），
  第二行其余字段「标签 值」按 = · = 串联；两行都 =:width 'stretch :wrap-mode 'word=，
  超出窗口自动折行，行高自适应，**不做任何字符省略**。
- 数据文本**禁止**经过 =--fit-text=：该函数只用于标题 / 图表标签（=--to-text-bars= 的图例列与
  =--fit-text-chart= 的逐行收敛）。
- 仍然按窗口宽度计算的只有：图表宽度（=--chart-width=）、tile 单元格宽度（=--tile-cell-width=，
  ETAF 会校验单元格文本必须 ≤ 它）、下钻弹窗宽度（=--dialog-width=）、文本图逐行宽度
  （=--fit-text-chart=）。内容宽度 = 窗口列数 − 面板左右占位 6 − 余量 1（=--content-cells=）。
- 宽度来源是 ETAF viewport（=etaf-runtime-viewport=，渲染期读取即建立响应式依赖，窗口缩放会触发

** 降级规则

| 场景 | 判据 | 行为 |
|---|---|---|
| ETAF 缺失 | =(require 'etaf nil t)= / =(require 'etaf-ui nil t)= 任一失败 | =display-warning= 提示安装 + =tabulated-list= 简版页；简版**含慢命令表与热点函数表两张表**并支持 =1=/=7=/=3= 切范围，不是空壳（I9） |
| 非图形 frame（batch / terminal） | =--graphic-p= 为 nil（=display-graphic-p= 且 =image-type-available-p 'svg=） | 图表组件返回 =--to-text-bars= 的字符图（=·= / =░= / =▒= / =▓= / =█=），不报错（I11） |
| 数据库打不开 / 查询失败 | analysis 返回 nil（已 =display-warning=） | 各区块显示「（无数据）」；=--load-snapshot= 再包一层 =condition-case= 双保险 |
| 页面 buffer 被 kill | =--auto-refresh= 发现 buffer 不存在 | 自动取消 timer，零残留 |

简版页（=tabulated-list=）一个 buffer 只支持一张表，故用区块标题行（=▸ 慢命令 TOP= /
=▸ 热点函数 TOP=）把两张表放进同一张表的连续行里。

** ETAF 实测踩坑清单（T8 实测，2026-10-24，Emacs 31.1）

1. **组件不是函数**（=fboundp= 为 nil）
   现象：=etaf-define-component= 定义的组件注册在 ETAF 的组件表里，不是 fboundp 可见的函数，
   用 =fboundp 'el-chronos-dashboard-app= 探测恒为 nil。
   应对：探测能力用 =etaf-mount= / =etaf-ui-svg-image= 的存在性（=el-chronos-dashboard-etaf-available-p=
   只看 feature 与组件 API 是否就位），组件间调用用 =etaf-view= 形式，不用 =funcall=。

2. **表格组件名是 =etaf-table=，不是 =etaf-ui-table=；=:row-key= 必填**
   现象：计划与 ADR 早期写作 =etaf-ui-table=，实际注册名是 =etaf-table=；缺 =:row-key= 时
   行身份无法稳定，=:on-row-press= 拿不到正确行。
   应对：统一用 =etaf-table=，并显式给 =:row-key (lambda (row) (alist-get :key row))=。

3. **=text= 内非字面量必须写 =(expr FORM)=**
   现象：=text= 只接受字面字符串 / 子组件；直接写 =(text (--to-text-bars …))= 会被当 DSL 语法，
   报语法错。
   应对：要插入求值结果一律 =(text (expr FORM))=。同理在组件树中要 mapcar 生成子树，
   也要写成 =(expr (mapcar …))=。

4. **列表属性必须 =(quote ...)=**
   现象：=:selected= 传 plist 时不加 =quote=，ETAF 把列表当代码求值，报 =void-function :title=。
   应对：=:selected (quote ,selection)=；任何「数据型列表」属性同理。

5. **重挂同一 buffer 必须先 =etaf-unmount=**
   现象：反复 =etaf-mount= 到同一个 =*el-chronos*= 而不卸载，ETAF 保留上一实例的 =:bindings=，
   弹窗与状态栏停在旧值（切范围看似无效）。
   应对：=--render-etaf= 里先 =(when-let* ((runtime (etaf-runtime-for-buffer buffer))) (etaf-unmount runtime))=。

6. **=:bindings= 必须用 =(etaf-value x)= 读**
   现象：直接引用 binding 符号（如 =page-state=）读到的是 ref 对象本身，不是当前值。
   应对：读状态一律 =(etaf-value page-state)= / =(etaf-value selected-state)=；写状态用
   =--set-range= / =--set-page= 改 plist 后重绘（不直接 setf ref）。

7. **无 polyline 图元，折线用 =etaf-ui-svg-path=**
   现象：=etaf-ui-svg= 只提供 =rect= / =circle= / =line= / =path= / =text= / =group=，
   没有 =polyline=。
   应对：折线生成 =d= 属性（=--polyline-d=：=M x y L x y …=）再走 =etaf-ui-svg-path=；
   =--sparkline= / =--trend-body= 都按此实现。

8. **batch 下 =etaf-mount= 可正常挂载并产生文本**
   现象：=emacs -Q --batch= 里 =etaf-mount= 能挂载并把组件树渲染成 buffer 文本
   （=--graphic-p= 为 nil，图表走字符图路径）。
   应对：ERT 可以直接断言页面文本（=test/el-chronos-ui-test.el= 的 ETAF 用例即由此而来），
   无需真实 GUI；但 SVG 图元的断言走纯函数（=--bar= / --scale= / --sparkline= / --bar-chart= /
   --heatmap= / --to-text-bars=）。

9. **宏的软依赖：顶层写 =etaf-define-component= 会让 =make lint= 误编**
   现象：=make lint= 用 =emacs -Q --batch -L .= 字节编译，ETAF 不在 load-path 时
   =etaf-define-component= / =etaf-view= 这两个宏无法展开，宏调用被编成普通函数调用，
   运行期即使 ETAF 在位也会失败（=void-function etaf-view=）。
   应对：组件定义式与挂载形式都退化为**数据**并用 =(eval FORM t)= 延迟展开：组件定义放
   =--component-forms=，挂载写 =(eval `(etaf-view …) t)=。代价是组件体不做编译期检查，
   故组件体只调用本文件已定义好的函数。

10. **=etaf-tile-grid= 的 =:cell-text= 必须单行且不超 =:cell-width=**
    现象：=tile-grid= 会校验单元格文本宽度，多行或被折行的文本会触发布局校验失败 / 显示错乱。
    应对：=--metric-text= 只产出「名称 值」短格式单行（=:cell-width 24= / =:cell-height 3=），
    换行由布局负责；图形 frame 下改走 =:cell-image=（SVG 指标卡），文本路径仅用于非图形 frame。

11. **=etaf-mount= 没有 =:background= / =:foreground=，背景要自己 remap**
    现象：以为 =etaf-mount= 像 =etaf-app-open= 一样接受背景参数，传进去被当作未知选项；
    而 =ebox--sync-canvas=（把根节点背景 remap 到 =default= face）只在**显示时**执行，
    batch / 首帧前读不到。
    应对：背景走两条通道 —— 根节点 =:background-color= / =:color=（主题色）+ 挂载后显式
    =(face-remap-set-base 'default …)=（=--apply-theme-canvas=，与 =etaf-app--paint-canvas= 同机制）。
    用 =set-base= 而不是 =add-relative=：重复渲染幂等，不会叠加。

12. **组件 prop 名为 =:key= 会被拒绝；prop 里写 =(expr …)= 会变成「调用 expr」**
    现象：=(etaf-define-component … (&key head detail key press))= 报
    "Component prop key is reserved by the View grammar"；prop 位置写 =:on-press (expr press)=
    时渲染期报 =void-function (expr)=（prop 的非字面量原样变成 hole 的 thunk）。
    应对：prop 名避开 =:key= / =:ref= 等 View 语法保留字（本项目用 =head= / =detail= / =press=）；
    prop 位置直接写变量名或函数调用，=(expr FORM)= 只用于 =text= 之类**子节点**位置。

13. **=etaf-theme-provide= 只能在组件 =:setup= / 渲染上下文中调用**
    现象：在顶层或 =:view= 里调会报 "ETAF provide requires Component setup or render context"。
    应对：放在根组件的 =:setup=（本项目 =--define-components= 中第一次渲染时求值），子树内所有
    内置组件的 token 解析自动命中；无需逐节点设色。

14. **=etaf-table= 的单元格是 =:overflow hidden :wrap-mode none=**
    现象：想靠 =:cell= 返回可换行 box 保住长文本，结果列仍不对齐（每行独立 track），且窄窗口下
    被裁切。详见「宽度策略与不截断」一节。
    应对：数据行改用卡片（=column= + =:wrap-mode 'word=）；表格只适合「短字段 + 定宽对齐」。

** 只读与 loopback 边界

- 只绑 =127.0.0.1=（=el-chronos-web--host= 是常量，不接受 =0.0.0.0=），端口 =el-chronos-web-port=（默认 8787）。
- **无鉴权**。loopback 只防 LAN 暴露，**不构成本机访问控制**：WSL2 mirrored 网络共享端口空间，
  Windows 侧进程可直接访问该端口（I8，见 [[file:../Readme.org][Readme]]「隐私边界」）。
- 默认不自动启动（=el-chronos-web-auto-start= 为 nil）；端口占用 → =user-error=，
  **不自动换端口**（I11）。用完 =M-x el-chronos-web-stop= 释放端口。
- 端口 =0= 时由内核分配：=el-chronos-web-start= 的 =message= 与 =user-error= 一律取
  =(process-contact PROC :service)= 反映**实际绑定**端口（取不到才回落入参），因此传 =0= 也不会
  提示「http://127.0.0.1:0/」。调用方可用 =(process-contact (el-chronos-web-start))= 核验。
- 路由表无写入 / 执行入口；CSV 导出也是只读查询 + 格式化。

** 单线程串行处理的含义

- 请求处理在 **Emacs 主线程同步执行**：=:filter= 收字节 → 凑到 =\r\n\r\n= → 解析请求行 → 一次响应
  → =Connection: close= + EOF 关闭。因此**不需要** keep-alive、分块传输、长连接超时管理。
- 后果一：响应时间 = 查询时间（SQLite 本地读取，毫秒级）；并发请求在 Emacs 里**排队**，
  不是并行——多个标签页同时刷新会串行处理。
- 后果二：单个慢查询会占住主线程（进而让采集的 timer 延迟）。因此列表接口都有 =limit= 上限
  （默认 20、最大 1000），堆栈默认 50，包占比不分页。
- 后果三：单请求累积上限 16KB（=--max-request-bytes=），超出返回 413，防畸形请求无限占内存。
- 单请求异常 → 500 且 server 继续服务（I11：不因一次坏请求整体挂掉）。
  **500 不回显内部错误**：浏览器只看到通用文案「请求处理失败。内部错误详见 Emacs 的 =*Messages*=。」，
  错误详情（常含绝对路径与 SQL 片段）经 =display-warning= 写到 Emacs 侧 =\*Messages\*=
  / =\*Warnings\*=，本机用户仍能排障——可见降级但不向浏览器泄露实现细节。

** 每页行数与内存（2026-10-24 实测，Emacs 31.1）

**症状**：打开 dashboard 数次后进程内存暴涨，隔离实例（=elisp-test=）OOM。

**量化**（batch + ETAF，fixture = 3000 会话 / 2 万命令 / 4800 函数行 / 6000 阻塞事件，
每次 =M-x el-chronos-dashboard= 后先 =garbage-collect= 再读 =garbage-collect= 的 USED 与
=/proc/self/status= 的 VmRSS）：

| 指标 | 修复前（每渲染） | 修复后（每渲染） |
|---|---|---|
| 交给 =etaf-table= 的行数 | 2161（=:sessions= 无行数上限 2101 行 + 其余 60） | 80（5 表各 ≤ 20） |
| =--tables= 的 =prin1= 长度 | 512 KB | 19.7 KB |
| 快照 =prin1= 长度 | 225 KB | 40 KB |
| GC 后存活 cons | 92 万 → 361 万（+62 万/次，线性不收敛） | 24.7 万 → 38 万（+3.3 万/次，采样窗口 flush 后回落到 24.7 万） |
| VmRSS | 133 MB → 304 MB（+26 MB/次） | 103 MB → 105 MB |
| 单次渲染耗时 | 25–34 s | 4–5 s |

**当前渲染单位**（2026-10-24 起）：行单位是卡片（=el-chronos-dashboard-card=）而不是
=etaf-table= 的行，但同样是**保留式 Host**（每卡一个 column Host + 两个 box），故
=el-chronos-dashboard-page-size= 这条上限仍然必须生效 —— 换布局不减少保留对象数。

**主因**（证据链，逐层排除）：
1. =el-chronos-analysis-sessions= 按时间窗查询且**无行数上限**（一年重启数千次即数千行），
   而 5 个表区块中 =:sessions= 标的是「不分页」，于是 =--tables= 把**整表**构造好交给 ETAF。
1. =etaf-table= 用 =:for (item ...)= 逐行创建**保留式行组件**（每行一个 row Host + 单元格
   子组件 + 行 key），行数直接等于保留对象数——不是「渲染时截断」能省的。
1. 每次挂载 =etaf-unmount= 只 =remhash= 旧 runtime，页对象要等 GC；而采集层开着 CPU 采样时
   （=el-chronos-mode 1=，10ms 间隔）GC 对采样栈保守扫描，旧页在采样日志 flush 前拿不回来
   → 会话表越大，「每渲染泄漏一页」越贵。
1. 排除项（实测均不是主因）：=--ensure-buffer-hooks= 的 =--hooked-buffers= 恒为 5、
   buffer 数恒为 7（首开 +2 后不增）；=--components-defined-p= 守卫生效（组件只 =eval= 一次）；
   =etaf--runtimes= 恒为 1（unmount 生效）；纯查询（不渲染）10 次的存活 cons 只 +0.5 万。

**修法**：
- =--render-rows=：**在构造行描述之前**截断——分页表取第 PAGE 页，不分页表只取前
  =el-chronos-dashboard-page-size= 行；标题如实写「已加载 N 条，显示前 M 条」。
- =--cap-rows= + =el-chronos-dashboard-max-rows=（200）：快照每个列表字段都封顶，
  挡 =:sessions= / =:trend= / =:heatmap= 这类无界查询。
- =--reload-snapshot=：重载前先把旧快照置 nil，查询期间不持有两代数据。
- =el-chronos-collect--internal-buffer-p=：内部 buffer（名字以空格开头，如 ETAF 的
  = *work*=）不补挂命令计时 hook（仍登记，避免重复判断）——顺带消掉「打开 dashboard 要碰
  全部 buffer」的观感负担。

**残余**：+3.3 万 cons/次是采样期间的保守保留，采集层每个 =el-chronos-sample-window-seconds=
窗口 flush 采样日志后回落到基线（实测 =--sample-tick= 后 38 万 → 24.7 万），属有界抖动，
且与行数成正比——所以行数上限是这条链路的第一道闸。回归用例见
=test/el-chronos-ui-test.el=（=dashboard-tables-cap-rows= / =dashboard-snapshot-cap-rows= /
=dashboard-repeat-open-no-growth=）。

**待实测**：ETAF 页面在 30 天真实数据下的首次渲染与切范围重绘耗时（TD-5）；
terminal 文本字符图的可读性；Web 页在 30 天数据下的火焰图渲染耗时。
