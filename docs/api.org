#+BEGIN_QUOTE
本文件按模块列出 el-chronos 的对外符号（函数 / 命令 / defcustom）、签名、返回值与一句话说明。
**兼容承诺**：不带双连字符的符号是对外接口，改动需在 =CHANGELOG.md= 的 =[Unreleased]= 记录
（破坏性改动另记 ADR）；**内部函数一律以 =--= 结尾，不承诺兼容**，可随时重命名或删除，
不要在用户配置里依赖它们。

单位约定（I4）：时间戳、耗时、桶起点一律**毫秒**；采样间隔用**纳秒**（仅内存，不落库）。
所有查询函数在数据库打不开或 SQL 出错时 =display-warning= 并返回 =nil=，**不向调用方抛错**（I6）。
#+END_QUOTE

* 概览：8 个模块

| 模块 | 文件 | 职责 | 对外符号数 |
|---|---|---|---|
| 入口 | =el-chronos.el= | 自定义组、minor mode、启停编排、错误降级 | 2 命令 + 21 defcustom |
| 归因 | =el-chronos-attrib.el= | 符号 → 源码文件 → 包 / 模块；命令上下文 | 4 |
| 存储 | =el-chronos-store.el= | SQLite schema（v5，13 表）、批量 flush、保留与 purge | 17 |
| 采集 | =el-chronos-collect.el= | 命令计时、心跳阻塞、profiler 窗口聚合、GC / 资源 / 启动打点 | 2 + 1 defcustom |
| 分析 | =el-chronos-analysis.el= | 22 个只读分析函数（另有 =names= 作为补全辅助，不计入）；22 = 23 个 public defun 减去 =names= | 22 |
| 报告 | =el-chronos-report.el= | org 报告、周报、CSV/JSON 导出、单命令剖析 | 5 + 1 defcustom |
| Web | =el-chronos-web.el= | 最小 HTTP server（19 条只读 GET 路由）+ 内嵌 Web dashboard | 4（**零 defcustom**；=el-chronos-web-open-browser= 物理落位在 =el-chronos.el=，已计入入口模块的 21 个） |
| 启动探针 | =el-chronos-startup-probe.el= | **零依赖**：early-init 起的加载打点 + 三个启动锚点（只写内存，不开库不写库） | 2 |

defcustom 合计 **23 个**：=el-chronos.el= 21 个 + =el-chronos-collect-notify-blocks=（collect）
+ =el-chronos-profile-save=（report）。后两个是历史分散项，**不迁移**（迁走会破坏用户已有的
=setq= 位置与 =custom-file= 记录）；新增的 defcustom 一律落 =el-chronos.el=。
计数口径按**定义物理落位**统计（不是按功能归属）：=el-chronos-web.el= 零 defcustom ——
=el-chronos-web-open-browser= 定义在 =el-chronos.el=，只在入口模块算一次。

可视化只有两种形态：**浏览器 Web dashboard**（=el-chronos-web.el=）与 **org 报告**（=el-chronos-report.el=），
没有 Emacs 内的独立页面模块。

=el-chronos-startup-probe.el= 是**可选侧文件**：由用户在 =early-init.el= 里
=(load "el-chronos-startup-probe" t t t)= 加载，不在 =el-chronos-mode= 生命周期内
（I5 例外，见 ADR-0006 D1）。它**不 require 任何 el-chronos 模块**，也不 require
=cl-lib= / =subr-x=（early-init 期 =straight/build-*= 还没建立）。

* 入口模块（=el-chronos.el=）

** 命令

| 符号 | 签名 | 返回 | 说明 |
|---|---|---|---|
| =el-chronos-mode= | =(ARG)=，global minor mode | — | 全局开关：=1= 启动采集、=-1= 零残留停止（I5）。幂等。 |
| =el-chronos-status= | =()=，interactive | 状态文本（同时 =message=） | 在 echo area 显示运行状态（是否运行、DB 路径、timer 数、会话 id 等）。 |

#+BEGIN_SRC elisp
(require 'el-chronos)
(el-chronos-mode 1)     ; 启动观测
(el-chronos-status)     ; 查看状态
(el-chronos-mode -1)    ; 停止，清理 timer / hook / profiler / 未 flush 缓冲
#+END_SRC

** defcustom（=el-chronos.el= 内 21 个，属于 =el-chronos= 组）

| 变量 | 默认值 | 类型 | 说明 |
|---|---|---|---|
| =el-chronos-enabled= | =t= | boolean | 总开关。为 nil 时 mode 仍可切换，但不启动采集。 |
| =el-chronos-sampling-interval-ns= | =10000000= | integer | profiler 采样间隔（纳秒，默认 10ms）。 |
| =el-chronos-sample-window-seconds= | =10= | integer | 采样窗口长度（秒）；每满一个窗口取走计数并重置。 |
| =el-chronos-heap-sample-windows= | =6= | integer | 每 N 个采样窗口取一次 Emacs 堆大小（≈ N × 窗口长度，默认约 60s）。堆采样稀疏，同小时只保留最后一个非空值（=COALESCE=）；Emacs < 31.1 无 =garbage-collect-heapsize= 时该列恒 NULL。 |
| =el-chronos-startup-top-n= | =50= | integer | 启动期包加载明细入库的条数上限（内存留全部、写库前按 ms 降序截断）。决定 =startup_phases= 每会话行数的上界（top-N + 3，=first-idle= 记录时 +4）。 |
| =el-chronos-heartbeat-seconds= | =0.25= | number | 心跳间隔（秒），用于检测**命令外**主线程停转。默认 **250ms**（v3 由 1 改为 0.25）：把 block / drift 两档的**高估上界从 1s 压到 250ms**。开销依据：实测相对开销 **+0.0357%**（[[file:architecture.org][docs/architecture.org]]「实测结论 13」，距 0.5% 预算余 14 倍），但该数字是 =emacs -Q --batch= 下测的，**GUI 主循环未验证**（只能作上界估计）。**硬约束**：本值必须小于 =el-chronos-drift-threshold-ms=，否则每次正常心跳间隔都会被判成 drift（代码不断言，调档见 [[file:operations.org][docs/operations.org]]）。 |
| =el-chronos-resource-sampling= | =t= | boolean | **是否采集 Emacs 进程资源与系统负载（v4，默认开启）**。采集项：进程 CPU（=process-attributes= 的 =time= 差分成 =cpu_ms= / =wall_ms=）、RSS（=rss=，KB）、线程数（=thcount=）、系统负载 1/5/15（=load-average= **需传 =t=** 才返回列表）。只查 =(emacs-pid)= **自己**，零副作用；复用既有采样 timer，**不新增 timer**。**不采系统内存**（=memory-info= 是整机内存，remote =default-directory= 下查的是远端主机）。取 =nil= 表示**完全不采**：连 =process-attributes= 都不调用（该分支直接返回，零开销）。口径见 [[file:operations.org][docs/operations.org]]「资源采集的开关与口径」。 |
| =el-chronos-block-threshold-ms= | =2000= | number | 心跳 drift 超过该值记一条 =block= 明细（毫秒）。v3 起 block **只覆盖命令外停转**（命令执行时间被 =--finish= 的基线重置切出 gap），=command= 列恒 =nil=。 |
| =el-chronos-drift-threshold-ms= | =500= | number | **命令外停转**的 drift 档阈值（毫秒，v3 新增）：超过即累加到 =hourly_drift= 小时聚合（只记次数 / 累计 / 最坏，**不记明细、不发提示**）；超过 =el-chronos-block-threshold-ms= 则记 block 档（两档互斥）。**语义限定「命令之外」**：命令内停转由 =commands= 的 =duration_ms= 负责，两表**不可相加**。**硬约束**：必须大于 =el-chronos-heartbeat-seconds= × 1000。真实频率未知（batch 只能注入人造延迟），建议上线观察一周后调档。 |
| =el-chronos-slow-command-threshold-ms= | =200= | number | 慢命令阈值（毫秒）。 |
| =el-chronos-db-path= | =<user-emacs-directory>/.local/state/chronos/chronos.sqlite= | file | 唯一的落库文件（I3）。 |
| =el-chronos-retention-days= | =30= | integer | 明细表（=commands= / =slow_events=）保留天数。 |
| =el-chronos-usage-granularity= | ='command= | choice（=command= / =file=） | 用法聚合维度。=file= 会记**被操作文件绝对路径**且永久保留，默认不记（I7）。 |
| =el-chronos-store-stack-top-n= | =200= | integer | 每会话每小时保留的栈样本条数上限（按 =samples= 淘汰）。 |
| =el-chronos-regression-window-days= | =7= | integer | 回归判定窗口长度（近 N 天 vs 前 N 天）。 |
| =el-chronos-regression-threshold= | =0.5= | number | 回归增长率阈值（0.5 = +50%）。 |
| =el-chronos-regression-min-samples= | =10= | integer | 回归判定要求的最小样本数（两窗口各自满足）。 |
| =el-chronos-web-port= | =8787= | integer | Web dashboard 端口（只绑 =127.0.0.1=，占用即失败不换端口）。 |
| =el-chronos-web-auto-start= | =nil= | boolean | 启用观测时是否顺带启动 Web（默认不启动）。程序化启动**绝不弹浏览器**（见 =el-chronos-web-open-browser=）。 |
| =el-chronos-web-open-browser= | =t= | boolean | **交互式**启动 Web dashboard 时是否自动用 =browse-url= 打开页面（默认开启）。=nil= 时只在 echo area 显示 URL。**只影响交互式调用**（=M-x el-chronos-web-start=）：程序化启动（=el-chronos-web-auto-start= 顺带起 server）绝不弹，否则每次启动 Emacs 都弹窗。打开失败只 =message= 提示并给出 URL，不影响 server 启动（I11：可见降级）。 |
| =el-chronos-config-watch-globs= | ='("early-init.el" "init.el" "lisp/init-*.el")= | (repeat string) | 计算 =session_meta.config-sig= 时要指纹化的文件清单，用 =file-expand-wildcards= **相对 =user-emacs-directory=** 展开。指纹是 =(相对路径 mtime size)= 排序后的 =secure-hash 'sha1=，**不含文件内容**。无匹配文件时**不写该键**（不写 NULL 值行）。 |

| =el-chronos-store-record-health= | =(HOUR-TS KEY VALUE)= | 无 | 累加采集器自监控计数（v2）。=KEY= 为固定枚举：=dropped-commands= / =dropped-events= / =flush-failures= / =flush-count= / =flush-ms= / =sample-misses=。库里是 **eventual** 值（flush 失败时无法写库，下一次成功 flush 补写）。 |

| =el-chronos-store-record-session-meta= | =(SESSION-ID KEY VALUE)= | 无 | 写会话级元数据（v2，=git-head= / =config-sig=）。**直接 =sqlite-execute= 写入、不走缓冲**（每会话一次的冷路径，立即可见、不占缓冲、失败可独立告警）；=VALUE= 为 nil 时**不写行**。 |
| =el-chronos-store-note-startup-ms= | =(MS)= | 无 | 登记待补写的 =sessions.startup_ms=，落库并入**下一次 flush 的既有事务**。**纯内存、零 IO**：不碰 sqlite、不告警、不登记 timer（见「内部函数约定」）。 |
| =el-chronos-store-flush= | =()=，interactive | 无 | 全部缓冲单事务写库（含 v2 / v3 / v4 新表 + 待补写的 =startup_ms=）；失败整体 ROLLBACK、丢弃本批、限流告警（10 分钟一次）。**一般不直接调用**：由 =el-chronos-mode= 与 5s flush timer 编排（=interactive= 只让 =M-x= 可用）。 |
| =el-chronos-purge= | =(&optional BEFORE)=，interactive | =((表名 . 删除行数) ...)= | 删除 =BEFORE=（epoch ms）之前的**全部**数据（含七张 =hourly_*= 与两张会话级表）：**共 13 张表**，删除顺序钉死（见 [[file:schema.org][docs/schema.org]]「purge 的 13 表删除顺序」）。=BEFORE= 为 nil 时清空全部 13 张表。与自动 retention 的区别是连聚合一起删。 |
| =el-chronos-store-vacuum= | =()=，interactive | =t= / =nil= | 对当前库执行 =VACUUM= 回收空间（不能在事务内）。 |

* 采集模块（=el-chronos-collect.el=）

| 符号 | 签名 | 返回 | 说明 |
|---|---|---|---|
| =el-chronos-collect-start= | =()=，interactive | =t= / =nil= | 启动采集：命令计时 hook（全局 + 每 buffer 局部补挂，TD-9）、错误标记 advice、心跳 timer、采样 timer 与 profiler。幂等。 |
| =el-chronos-collect-stop= | =()=，interactive | =t= / =nil= | 停止采集并清空全部状态，保证零残留（I5）。幂等。 |

** =make autoloads= 的作用与产物

#+BEGIN_SRC sh
make autoloads      # → 仓库根 el-chronos-autoloads.el（约 221 行）
grep -n '^(autoload' el-chronos-autoloads.el
#+END_SRC

生成结果里每条都指向自己的定义文件（不是包名）：

#+BEGIN_SRC elisp
(autoload 'el-chronos-mode "el-chronos" nil t)             ; 定义文件即 el-chronos.el
(autoload 'el-chronos-report "el-chronos-report" nil t)    ; 定义文件是报告模块
#+END_SRC

- **不入库**：生成物与源码必然漂移，按需重建即可（=.gitignore= 已忽略）。
- **不进 L1/L2**：Makefile 的 =EL_FILES= 显式排除该文件，否则生成后 =make check-parens= /
  =make lint= 的检查范围会随生成物变化。
- **实现分流**：Emacs 29.1+ 用 =loaddefs-generate=，更早版本回退 =make-directory-autoloads=
  （ERT 用例同源守卫，不硬编码单一实现）。

** 配置侧写法

推荐形态是 straight =:local-repo= recipe（本地开发仓 + upstream 识别，与 =seshat-reader= 同款）：

#+BEGIN_SRC elisp
(use-package el-chronos
  :straight (el-chronos
             :type git
             :host github
             :repo "awerdx520/el-chronos"
             :branch "master"
             :local-repo "/home/thomas/Workspace/el-chronos"
             :files ("el-chronos*.el" (:exclude "el-chronos-autoloads.el"))
             :build (:not compile native-compile))
  :demand t)
#+END_SRC

straight 的 autoloads 步骤依据包侧 cookie 生成 =build-<ver>/el-chronos/el-chronos-autoloads.el=
并自动加载，因此**不必**逐条手写 =(autoload SYM "定义文件")=。要点只有四条：
=:straight= 必须写成完整 recipe（本机 =straight-use-package-by-default= 为 =t=，缺了它 straight
会去远端解析安装）、=:local-repo= 下游跑 =straight-pull-package= / =straight-checkout-package=
会改到开发仓本身、新增或改名 interactive 命令后须 =M-x straight-rebuild-package RET el-chronos=
刷新 autoloads、**需要「仓库缺失就降级」时必须用 =if= 包住整个 =use-package=**——=:if= / =:when=
包不住 =:straight= 生成的安装调用（实测展开仍是 =(progn (straight-use-package …) (when COND …))=，
条件为假照样去 clone；正确形态的展开把该调用关进 =if= 的 then 分支）。

完整逐项解释与陷阱见 [[file:operations.org][docs/operations.org]]「方式 A / 方式 C」与「静默陷阱」，
面向使用者的简版见 [[file:../Readme.org][Readme.org]]「安装」。若坚持 =:load-path= 形态（无 straight），
则须逐条 =(autoload SYM "定义文件")=，库名规则见下一节。

** 为什么 autoload 库名必须是定义文件

=(autoload SYM "LIB" ...)= 的 =LIB= 是「首次调用时要 =load= 哪个库文件」。若把报告命令声明成
包名——=(autoload 'el-chronos-report "el-chronos")=——首次 =M-x el-chronos-report= 会去加载
=el-chronos.el=，而该文件**不** =require= =el-chronos-report=（mode 启动时只软加载
=el-chronos-store= / =el-chronos-collect=），于是命令没被定义，Emacs 报
=Autoloading file ... failed to define function=（实测原文）。

这也正是 =use-package= 的 =:autoload= / =:commands= 无法直接用于跨文件入口的原因：这两个关键字
生成的 autoload 库名**恒为包名**（=:autoload= 复用 =:commands= 的 normalizer，只吃符号，
没有 per-symbol 文件名语法）。所以手写 autoload（=:load-path= 形态）必须在 =:init= 里显式
=(autoload SYM "FILE")=；而 straight 的 autoloads 步骤直接读 cookie 生成、天然带定义文件名，
这也是推荐 =:local-repo= recipe 的原因之一。
配置侧排查步骤见 [[file:operations.org][docs/operations.org]]「排障：=M-x= 提示命令未定义」。

* 内部函数约定

- 以 =--=（双连字符）结尾的是内部实现：=el-chronos--start= / =el-chronos-attrib--classify-path= /
  =el-chronos-store--flush= / =el-chronos-collect--pre-command= / =el-chronos-analysis--range= /
  =el-chronos-report--content= / =el-chronos-web--dispatch= 等。
- **不承诺兼容**：可随时重命名、改签名或删除；用户配置与外部集成不得依赖。
- **采样归因口径的两处内部处置**（2026-10-25，口径见 [[file:architecture.org][docs/architecture.org]]「采样归因口径」）：
  =el-chronos-collect--accumulate-entry= 对 nil 帧（profiler 尾部填充 / 未解析帧）**不计入**
  self / total（判据 =(and X (symbolp X))=，因 =(symbolp nil)= 为 =t=）；栈序列化前经
  =el-chronos-collect--trim-trailing-nils= 裁掉尾部 nil，全 nil 栈不写 =hourly_stacks=。
  归因侧的对应处置是 =el-chronos-attrib--builtin-primitive-p=（符号分支前置短路 → =built-in=）。
- **三条与内部实现强耦合的约定**（v2 / v3，2026-10-25）：
  - =el-chronos-store-note-startup-ms= 虽是**对外符号**（无 =--=），但**只能从采集侧的
    =after-init-hook= 回调调用**，且调用方必须保证「启动期零 IO」：它不碰 sqlite、不告警、
    不登记 timer，只把毫秒值放进一个 defvar；落库由下一次 =el-chronos-store-flush= 在既有事务内
    用 =UPDATE sessions SET startup_ms = ? WHERE id = ? AND startup_ms IS NULL= 补写（=IS NULL=
    守卫防覆盖已正确写入的值）。**禁止为它新增 timer**（复用既有 5 秒 flush timer 即可，I5 清理
    清单不必扩）；该 UPDATE 失败只记录并保留 pending，不阻断其余表写入，COMMIT 成功后才清 pending。
  - =el-chronos-store--record-session-meta-1 (DB SESSION-ID KEY VALUE)= 是 =session_meta= 的
    **显式句柄版**写入函数：不依赖全局 =el-chronos-store--db=。原因：=--ensure-session= 建会话行
    时全局句柄可能尚未赋值，purge 重建会话走的也是调用方持有的句柄。=VALUE= 为 nil 或任一 id
    为 nil 时**直接返回 nil、不写行**（KV 空值无信息量，且会让「取不到」与「取了但为空」不可区分）；
    对外入口 =el-chronos-store-record-session-meta= 只补一次「全局句柄是否可用」的门。
  - =el-chronos-collect--heartbeat-check (&optional NOW)= 是「命令外停转」的**单一判定入口**
    （v3）：**三处调用、两种职责，不许统一**。① 心跳 timer（=--heartbeat= 是只调它的薄壳）→
    判定 + 重置；② =--pre-command=（每条命令开始前）→ 补判 + 重置（命令外时间的最后一个可观测
    时机）；③ =--finish=（命令结算）→ **只做纯 =(setq --last-heartbeat (float-time))=，绝不调本
    函数** —— 那里调它会让 =gap= 恰等于刚执行完的命令时长，命令时长被记成 block / drift，
    双记（TD-11 ③）立刻复活。判定链是「无条件推进基线 → 抑制门（=--suppress-block-p=）→
    兜底门（=--pending-p=）→ block / drift 分档」，两档共用同一对门。=condition-case= **必须在
    本函数内部**：=--pre-command= 自身没有它，异常逃出去会经 =pre-command-hook= 中断用户正在
    执行的命令。三处调用形态由用例 =heartbeat-check-is-single-source-of-truth= 守门。
- **v4 的两条交接约定（探针 → collect → store）**（2026-10-26）：
  - =el-chronos-collect--startup-take-probe ()= 是**唯一交接点，两个调用来源共用、禁止分叉**：
    ① =--startup-instrument=（mode 启用时的首次交接）；② 探针 =--finish= 的**软调用**
    （补写「首次 take 之后到启动收尾之间」又加载的包）。判据三连，缺一返回 nil：
    =(fboundp 'el-chronos-startup-probe-take)=（用户没在 early-init 里 load → 完全走原有路径）、
    =:anchors= 与 =:loads= **至少一个非空**（只看探针的 =:captured-p= 不够，它可能为真而一条
    可写数据都没有）、=el-chronos--session-id= 非 nil。**会话守卫必须在 =take= 之前**
    （=and= 短路）：此时探针内存里的 =:loads= **不会被清空**，用户之后真启用 mode 时下一次交接
    仍能补上。**collect 绝不 =require= 探针** —— 它是可选侧文件。
  - =el-chronos-collect--collect-resources ()= 是资源采集的唯一入口：与 =--collect-gc= 并列、
    **同在其 =(when el-chronos-collect--sampling-p …)= 之外**（profiler 启动失败时资源趋势不该
    陪葬）；整段包 TRAMP 守卫 =(let ((default-directory temporary-file-directory)) …)=；
    逐字段判空、=nil= 表示「本窗口没采到」（**绝不用 0 冒充**）；首窗口只建基线不写库；
    **复用既有采样 timer，不新增 timer**（实测结论 13 第 4 条：成本在事件循环唤醒而非回调）。
  - 探针侧的对应约定（=el-chronos-startup-probe.el=）：=-data= **纯只读**（可反复调用拿同一份，
    排障 / 断言用）；=-take= **增量**（=:anchors= 只读不重置 —— 重复写同 phase 由 =startup_phases=
    主键 upsert 吸收幂等；=:loads= 取走即 =clrhash=）；=--finish= **幂等**且必须 =cancel-timer=
    **两个** timer（=--finish-timer= 与 =--fallback-timer=，漏一个就是探针侧遗留 timer，
    I5 在此无覆盖）；探针**不 require** 任何 el-chronos 模块（反向交接靠 =fboundp= 软调用）。
- 采集路径（hook / timer / profiler 回调）中的内部函数一律 =condition-case= 包裹，失败降级
  继续，不向宿主抛错（I6）。

* 启动探针模块（=el-chronos-startup-probe.el=，2 个对外接口）

**零依赖**：不 require 任何 el-chronos 模块，也不 require =cl-lib= / =subr-x= —— early-init 期
=straight/build-*= 还没建立，任何 require 都可能失败并打断启动。它**不开库、不建库、不写库**
（SQLite 与 flush 事务全部留给 collect），启动路径上不出现任何可能阻塞的 IO。

| 符号 | 签名 | 返回 | 说明 |
|---|---|---|---|
| =el-chronos-startup-probe-data= | =()= | plist =(:anchors ALIST :loads ALIST :captured-p BOOL)= 或 =nil= | **纯只读快照**：不清空、不重置任何状态，可反复调用拿同一份数据（排障与断言用）。=:anchors= 是 phase 符号 → 相对 =before-init-time= 的毫秒（按记录顺序，早→晚）；=:loads= 是 library 名 → 累计毫秒（按毫秒降序）。永不抛错（异常时返回 nil）。 |
| =el-chronos-startup-probe-take= | =()= | 同上的 plist | **取走数据（增量语义）**：=:anchors= **只读不重置**（重复 take 返回同一份，写库侧靠 =startup_phases= 主键 upsert 吸收幂等）；=:loads= **取走即清空**（=clrhash=，第二次 take 的 =:loads= 为空）；=:captured-p= 在清空前算好，故与是否清空无关。永不抛错。 |

#+BEGIN_SRC elisp
;; early-init.el（两行；NOERROR 语义，仓库搬走后静默降级）
(load "/home/thomas/Workspace/el-chronos/el-chronos-startup-probe" t t t)

;; 运行时查看快照（只读，可反复调用）
(plist-get (el-chronos-startup-probe-data) :anchors)
#+END_SRC
