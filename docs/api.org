#+BEGIN_QUOTE
本文件按模块列出 el-chronos 的对外符号（函数 / 命令 / defcustom）、签名、返回值与一句话说明。
**兼容承诺**：不带双连字符的符号是对外接口，改动需在 =CHANGELOG.md= 的 =[Unreleased]= 记录
（破坏性改动另记 ADR）；**内部函数一律以 =--= 结尾，不承诺兼容**，可随时重命名或删除，
不要在用户配置里依赖它们。

单位约定（I4）：时间戳、耗时、桶起点一律**毫秒**；采样间隔用**纳秒**（仅内存，不落库）。
所有查询函数在数据库打不开或 SQL 出错时 =display-warning= 并返回 =nil=，**不向调用方抛错**（I6）。
#+END_QUOTE

* 概览：7 个模块

| 模块 | 文件 | 职责 | 对外符号数 |
|---|---|---|---|
| 入口 | =el-chronos.el= | 自定义组、minor mode、启停编排、错误降级 | 2 命令 + 18 defcustom |
| 归因 | =el-chronos-attrib.el= | 符号 → 源码文件 → 包 / 模块；命令上下文 | 4 |
| 存储 | =el-chronos-store.el= | SQLite schema（v2，10 表）、批量 flush、保留与 purge | 15 |
| 采集 | =el-chronos-collect.el= | 命令计时、心跳阻塞、profiler 窗口聚合、GC / 启动打点 | 2 + 1 defcustom |
| 分析 | =el-chronos-analysis.el= | 17 个只读聚合查询 | 17 |
| 报告 | =el-chronos-report.el= | org 报告、周报、CSV/JSON 导出、单命令剖析 | 5 + 1 defcustom |
| Web | =el-chronos-web.el= | 最小 HTTP server（17 条只读 GET 路由）+ 内嵌 Web dashboard | 3 |

defcustom 合计 **20 个**：=el-chronos.el= 18 个 + =el-chronos-collect-notify-blocks=（collect）
+ =el-chronos-profile-save=（report）。后两个是历史分散项，**不迁移**（迁走会破坏用户已有的
=setq= 位置与 =custom-file= 记录）；新增的 defcustom 一律落 =el-chronos.el=。

可视化只有两种形态：**浏览器 Web dashboard**（=el-chronos-web.el=）与 **org 报告**（=el-chronos-report.el=），
没有 Emacs 内的独立页面模块。

* 入口模块（=el-chronos.el=）

** 命令

| 符号 | 签名 | 返回 | 说明 |
|---|---|---|---|
| =el-chronos-mode= | =(ARG)=，global minor mode | — | 全局开关：=1= 启动采集、=-1= 零残留停止（I5）。幂等。 |
| =el-chronos-status= | =()=，interactive | 状态文本（同时 =message=） | 在 echo area 显示运行状态（是否运行、DB 路径、timer 数、会话 id 等）。 |

#+BEGIN_SRC elisp
(require 'el-chronos)
(el-chronos-mode 1)     ; 启动观测
(el-chronos-status)     ; 查看状态
(el-chronos-mode -1)    ; 停止，清理 timer / hook / profiler / 未 flush 缓冲
#+END_SRC

* 归因模块（=el-chronos-attrib.el=）

| 符号 | 签名 | 返回 | 说明 |
|---|---|---|---|
| =el-chronos-attrib-file= | =(SYMBOL)= | 源码文件路径字符串或 =nil= | =symbol-file= + native-comp =.eln= 兜底；取不到返回 nil。 |
| =el-chronos-attrib-package= | =(SYMBOL-OR-PATH)= | 包名字符串，失败为 ="unknown"= | **符号分支先**判 C 原语 / 内置特殊形式 / profiler 伪符号（=el-chronos-attrib--builtin-primitive-p=）→ =built-in=，命中即**短路**（不调 =symbol-file=、不写缓存）；判据**排除** =native-comp-function-p= 为 t 的 native-comp 函数（Emacs 30+ 的 =subrp= 对它们也为 t，短路会绕过 =.eln= 反查归因——它们仍走 =symbol-file= → =.eln= 反查）；未命中才走 =symbol-file= → 路径分类：straight 包 / =lisp/init-*.el= 模块 / site-lisp / =built-in=；**任何失败都返回 ="unknown"=、不抛错**（I6）。 |
| =el-chronos-attrib-context= | =()= | plist =(:mode MODE :project BASENAME :file PATH-or-nil)= | 当前命令上下文。=:project= 只取项目 **basename**（I7）；=:file= 仅在 =el-chronos-usage-granularity= 为 =file= 时非 nil。 |
| =el-chronos-attrib-clear-cache= | =()=，interactive | 清除条目数 | 清空符号归因缓存（重载包之后用）。 |

(el-chronos-attrib-package 'save-buffer)   ; => "built-in"
(el-chronos-attrib-package "/some/unknown/path.el") ; => "unknown"
(el-chronos-attrib-context)                ; => (:mode emacs-lisp-mode :project "el-chronos" :file nil)
#+END_SRC

| 符号 | 签名 | 返回 | 说明 |
|---|---|---|---|
| =el-chronos-store-open= | =(&optional PATH)= | SQLite 句柄或 =nil= | 打开（或复用）数据库：pragma、=user_version= 检查与迁移、幂等；失败返回 nil 且已告警。 |
| =el-chronos-store-close= | =()= | =t= / =nil= | flush 缓冲 → 取消 flush timer → 关库 → 清状态。 |
| =el-chronos-store-record-command= | =(EVENT)= | 无 | 命令事件入缓冲（plist，键见 =commands= 表）。 |
| =el-chronos-store-record-slow-event= | =(EVENT)= | 无 | 慢事件 / 阻塞事件入缓冲。 |
| =el-chronos-store-record-usage= | =(HOUR-TS DIMENSION KEY COUNT DURATION-MS)= | 无 | 累加小时用量；=DIMENSION= 取 =command= / =mode= / =project= / =file=。 |
| =el-chronos-store-record-function-samples= | =(HOUR-TS FUNCTION FILE PACKAGE SELF-MS TOTAL-MS SAMPLES)= | 无 | 累加小时函数聚合（upsert）。 |
| =el-chronos-store-record-stacks= | =(HOUR-TS STACKS)= | 无 | 累加小时栈样本；=STACKS= 为 =((STACK-JSON . SAMPLES) ...)=。 |
| =el-chronos-store-record-gc= | =(HOUR-TS GC-COUNT GC-MS HEAP-BYTES)= | 无 | 累加小时 GC 统计（v2）。=HEAP-BYTES= 为 nil 表示本窗口无堆样本 → 该行 =heap_bytes= **保持上一次观测值**（=COALESCE=，last-observation-carried-forward）；只有非 nil 才覆盖。 |
| =el-chronos-store-record-health= | =(HOUR-TS KEY VALUE)= | 无 | 累加采集器自监控计数（v2）。=KEY= 为固定枚举：=dropped-commands= / =dropped-events= / =flush-failures= / =flush-count= / =flush-ms= / =sample-misses=。库里是 **eventual** 值（flush 失败时无法写库，下一次成功 flush 补写）。 |
| =el-chronos-store-record-startup-phase= | =(SESSION-ID PHASE MS)= | 无 | 记录启动阶段耗时（v2）。=PHASE= 取 =mode-start= / =after-init= / =startup= / =first-idle=，包加载明细用 ="load:<library>"=；同 =(SESSION-ID, PHASE)= 重复打点**覆盖**。 |
| =el-chronos-store-record-session-meta= | =(SESSION-ID KEY VALUE)= | 无 | 写会话级元数据（v2，=git-head= / =config-sig=）。**直接 =sqlite-execute= 写入、不走缓冲**（每会话一次的冷路径，立即可见、不占缓冲、失败可独立告警）；=VALUE= 为 nil 时**不写行**。 |
| =el-chronos-store-note-startup-ms= | =(MS)= | 无 | 登记待补写的 =sessions.startup_ms=，落库并入**下一次 flush 的既有事务**。**纯内存、零 IO**：不碰 sqlite、不告警、不登记 timer（见「内部函数约定」）。 |
| =el-chronos-store-flush= | =()= | 无 | 全部缓冲单事务写库（含 v2 四表 + 待补写的 =startup_ms=）；失败整体 ROLLBACK、丢弃本批、限流告警（10 分钟一次）。 |
| =el-chronos-purge= | =(&optional BEFORE)=，interactive | =((表名 . 删除行数) ...)= | 删除 =BEFORE=（epoch ms）之前的**全部**数据（含五张 =hourly_*= 与两张会话级表）：**共 10 张表**，删除顺序钉死（见 [[file:schema.org][docs/schema.org]]「purge 的 10 表删除顺序」）。=BEFORE= 为 nil 时清空全部 10 张表。与自动 retention 的区别是连聚合一起删。 |
| =el-chronos-store-vacuum= | =()=，interactive | =t= / =nil= | 对当前库执行 =VACUUM= 回收空间（不能在事务内）。 |

(el-chronos-store-open)      ; 幂等；打不开返回 nil

(el-chronos-purge)           ; 清空全部历史
(el-chronos-store-vacuum)    ; 回收文件空间
#+END_SRC

* 采集模块（=el-chronos-collect.el=）

| 符号 | 签名 | 返回 | 说明 |
|---|---|---|---|
| =el-chronos-collect-start= | =()= | =t= / =nil= | 启动采集：命令计时 hook（全局 + 每 buffer 局部补挂，TD-9）、错误标记 advice、心跳 timer、采样 timer 与 profiler。幂等。 |
| =el-chronos-collect-stop= | =()= | =t= / =nil= | 停止采集并清空全部状态，保证零残留（I5）。幂等。 |
| =el-chronos-collect-notify-blocks= | defcustom，默认 =nil= | =(choice (const nil) (const messages) (const t))= | 心跳检测到阻塞时**如何提示**（不影响采集与记录：=slow_events(kind="block")= 恒照记）。=nil= 静默；=messages= 只写 =*Messages*=（=(let ((inhibit-message t)) (message ...))=，不占 echo area）；=t= 在 echo area 提示（旧语义）。详见 [[file:operations.org][docs/operations.org]]「阻塞提示」。 |
| =el-chronos-collect--suppress-block-p= | defvar，默认 =nil= | boolean | **跨模块控制变量**：声明在 collect 侧（=el-chronos-collect.el=），**report 与 Web 侧各自绑定**（=el-chronos-report--without-block-events= 在报告生成期间、=el-chronos-web--without-block-events= 在请求处理期间各自 =let= 为 =t=；后者是前者的内联重复实现，为保持 web 零额外依赖，两处改动需同步），**collect 侧读取**（=el-chronos-collect--heartbeat= 用 =bound-and-true-p= 判断：非 =nil= 时跳过阻塞判定，只把 =--last-heartbeat= 推进到当前时刻，故解除绑定后不会补记整段 gap）。report 与 web 各自必须先 =defvar= 同名声明，否则跨模块 =let= 绑定未声明变量会 =void-variable=；两侧同名同义，重复声明无副作用。语义上它只抑制「重查询耗时的假阻塞」——其间真实发生的阻塞同样不记，属有意取舍。 |
| =el-chronos-collect--last-heartbeat= | defvar，默认 =nil= | 浮点秒 | 上一次心跳的实际触发时刻。**跨模块写入点**有三个：report 侧在报告生成结束、Web 侧在请求处理结束（两者都在各自的 =unwind-protect= 清理段）重设基线，以及 collect 心跳自身在抑制期间推进基线；目的都是避免补跑的心跳把整段非采集耗时记成阻塞（详见 [[file:architecture.org][docs/architecture.org]]「自观测抑制（report / Web）」）。 |

一般**不直接调用**：由 =el-chronos-mode= 编排（=--start= / =--stop=）。单独加载 collect 时对
store / attrib 是软引用（=declare-function= + =fboundp= 守卫）。

* 分析模块（=el-chronos-analysis.el=，17 个查询）

=RANGE= 取 ='1d= / ='7d= / ='30d=（按当前时刻倒推，上界含当前毫秒 +1 毫秒避免漏行），
或显式半开区间 ='(START . END)=（epoch 毫秒）。全部只读，返回 plist 或 list of plist；
失败返回 =nil= 并 =display-warning=。

| 符号 | 签名 | 返回 | 说明 |
|---|---|---|---|
| =el-chronos-analysis-overview= | =(RANGE)= | plist | 概览 6+1 指标：=:commands= =:blocked-ms= =:slow-commands= =:samples= =:db-size= =:startup-ms=（近 10 次有效会话中位数）= =:sessions= |
| =el-chronos-analysis-top-functions= | =(RANGE &optional LIMIT INCLUDE-GC)= | list of plist | 热点函数，按 self 降序；元素 =(:function :file :package :self-ms :samples :pct)=；默认排除 ="Automatic GC"= |
| =el-chronos-analysis-slow-commands= | =(RANGE &optional LIMIT)= | list of plist | 命令排行，按总耗时降序；=(:name :count :total-ms :max-ms :avg-ms :aborted)= |
| =el-chronos-analysis-package-breakdown= | =(RANGE &optional LIMIT)= | list of plist | 包 / 模块占比；=(:package :self-ms :pct)=；=unknown= 与 =GC= 恒排末尾 |
| =el-chronos-analysis-trend= | =(RANGE &optional BUCKETS)= | list of plist | 分桶趋势；=(:bucket :samples :slow-commands :blocked)=；空桶不返回 |
| =el-chronos-analysis-gc-trend= | =(RANGE &optional BUCKETS)= | plist | **GC 与内存趋势（v2）**。=:range= =:bucket-span= =:buckets= =:gc-total= =:heap-latest=；=:buckets= 元素 =(:bucket :gc-count :gc-ms :heap-bytes)=。三条关键约定：① =:heap-bytes= 取桶内**按 =hour_ts= 升序最后一个非 NULL 值**（瞬时量：求和没意义、平均会被采样间隔拉偏），桶内全 NULL 时为 nil；② 只在 Emacs 31.1+ 有值（更低版本恒 nil，不是数据丢失）；③ 会话首个采样窗口只建基线，可能出现 =gc-count= / =gc-ms= 全 0 的桶（那是基线桶，不等于「没有发生 GC」）。**无数据时返回 plist（=:buckets= 为 nil）而不是 nil**，避免调用方判空分支分叉。 |
| =el-chronos-analysis-heatmap= | =(RANGE &optional LIMIT)= | list of plist | 命令 × 时间桶热力；=(:bucket :command :count :duration-ms)= |
| =el-chronos-analysis-stacks= | =(RANGE &optional LIMIT)= | list of plist | 调用栈排行；=(:stack :samples :pct)=，=:stack= 第 0 帧是 leaf；默认 50 |
| =el-chronos-analysis-sessions= | =(RANGE)= | list of plist | 会话列表，按启动时间降序；=(:id :started-at :startup-ms :emacs-version :host)= |
| =el-chronos-analysis-startup-breakdown= | =(&optional SESSION-ID)= | plist | **启动耗时分解（v2）**。=:session-id= =:started-at= =:startup-ms= =:phases= =:loads=；=:phases= 为 =((PHASE MS) ...)=（固定顺序 =mode-start= → =after-init= → =startup= → =first-idle=，缺的跳过），=:loads= 为 =((LIBRARY MS) ...)=（=phase= 以 ="load:"= 开头的行，按 ms 降序、前缀已去掉、入库前已按 =el-chronos-startup-top-n= 截断）。=SESSION-ID= 省略时取最近一次有启动数据的会话。**两条口径**：① 包加载耗时是相邻 =after-load-functions= 回调的时间差，属**近似归因**；② 覆盖范围受限——mode 在启动结束后启用时只有 =mode-start= 一个锚点、无包加载明细（物理边界，见 [[file:operations.org][docs/operations.org]]）。无数据时返回**同构空结构**（不返回 nil）。 |
| =el-chronos-analysis-health= | =(RANGE)= | plist | **采集器自监控（v2）**。=:dropped-commands= =:dropped-events= =:flush-failures= =:flush-count= =:flush-ms= =:flush-avg-ms= =:sample-misses= =:ok-p= =:rows=。关键约定：=:ok-p= 只看四个「坏消息」键（=dropped-commands= / =dropped-events= / =flush-failures= / =sample-misses=）是否全 0；**=:rows= 是区分「本期无异常」与「本期无数据」的唯一依据**——一条 health 行都没有时 =:ok-p= 同样为 t，只看 =:ok-p= 会把「没采集」读成「一切正常」（报告与 Web 都按 =:rows= 先行分支）。计数是 **eventual** 值（flush 失败要等下一次成功 flush 才可见）。 |
| =el-chronos-analysis-config-history= | =(RANGE)= | plist | **配置变更时间线（v2）**。=:sessions= 元素 =(:id :started-at :git-head :config-sig :changed)=（按 =started_at= 升序）；=:changes= 为 =:changed= 为 t 的会话数。关键约定：=:changed= 表示**与前一个会话相比** =(git-head, config-sig)= 有变化，**=nil= 有两种含义且本层不区分**——① 首会话（没有「前一个」，无从比较）；② 与前一会话相比标记无差异；调用方若需区分请**自行判断会话序号**（=:sessions= 的首个元素即第一个会话）；引入三态（=:n/a= / nil / t）属行为变更、未实施，见技术债 TD-20；两个键都为 nil 的相邻会话视为没变化（无法断言配置变了，谎报比漏报更糟）。=git-head= / =config-sig= 为 nil 表示**未取到**（store 层取不到就不写行），不是「取了但为空」。空库返回 =(:sessions nil :changes 0)=。 |
| =el-chronos-analysis-blocking-events= | =(RANGE &optional LIMIT)= | list of plist | 命令外阻塞事件，按耗时降序；=(:id :ts :duration-ms :kind :command :mode :project)= |

* 内部函数约定

- 以 =--=（双连字符）结尾的是内部实现：=el-chronos--start= / =el-chronos-attrib--classify-path= /
  =el-chronos-store--flush= / =el-chronos-collect--pre-command= / =el-chronos-analysis--range= /
  =el-chronos-report--content= / =el-chronos-web--dispatch= 等。
- **不承诺兼容**：可随时重命名、改签名或删除；用户配置与外部集成不得依赖。
- **采样归因口径的两处内部处置**（2026-10-25，口径见 [[file:architecture.org][docs/architecture.org]]「采样归因口径」）：
  =el-chronos-collect--accumulate-entry= 对 nil 帧（profiler 尾部填充 / 未解析帧）**不计入**
  self / total（判据 =(and X (symbolp X))=，因 =(symbolp nil)= 为 =t=）；栈序列化前经
  =el-chronos-collect--trim-trailing-nils= 裁掉尾部 nil，全 nil 栈不写 =hourly_stacks=。
  归因侧的对应处置是 =el-chronos-attrib--builtin-primitive-p=（符号分支前置短路 → =built-in=）。
- **两条与内部实现强耦合的约定**（v2，2026-10-25）：
  - =el-chronos-store-note-startup-ms= 虽是**对外符号**（无 =--=），但**只能从采集侧的
    =after-init-hook= 回调调用**，且调用方必须保证「启动期零 IO」：它不碰 sqlite、不告警、
    不登记 timer，只把毫秒值放进一个 defvar；落库由下一次 =el-chronos-store-flush= 在既有事务内
    用 =UPDATE sessions SET startup_ms = ? WHERE id = ? AND startup_ms IS NULL= 补写（=IS NULL=
    守卫防覆盖已正确写入的值）。**禁止为它新增 timer**（复用既有 5 秒 flush timer 即可，I5 清理
    清单不必扩）；该 UPDATE 失败只记录并保留 pending，不阻断其余表写入，COMMIT 成功后才清 pending。
  - =el-chronos-store--record-session-meta-1 (DB SESSION-ID KEY VALUE)= 是 =session_meta= 的
    **显式句柄版**写入函数：不依赖全局 =el-chronos-store--db=。原因：=--ensure-session= 建会话行
    时全局句柄可能尚未赋值，purge 重建会话走的也是调用方持有的句柄。=VALUE= 为 nil 或任一 id
    为 nil 时**直接返回 nil、不写行**（KV 空值无信息量，且会让「取不到」与「取了但为空」不可区分）；
    对外入口 =el-chronos-store-record-session-meta= 只补一次「全局句柄是否可用」的门。
- 采集路径（hook / timer / profiler 回调）中的内部函数一律 =condition-case= 包裹，失败降级
  继续，不向宿主抛错（I6）。
